# 대기열에서 기다리기

요청한 GPU 자원에 여유가 없더라도 세션 생성 요청은 **거부되지 않습니다**. 대기열(Queue)에 등록되어 가용 자원이 확보되면 세션이 자동으로 시작됩니다. 대기 중에는 브라우저 탭을 닫아도 안전합니다.

![대기열](/img/screens/queue.png)

## 대기열 상태 정보

| 항목 | 설명 |
|---|---|
| **세션** | 대기 중인 세션 이름입니다. 클릭 시 상세 페이지로 이동합니다. |
| **위치** | 대기 순번입니다 (`#1`이 다음 실행 순번). |
| **예상 대기** | 대기 시간 예측 데이터 기반의 예상 시간이며, 데이터가 부족한 경우 `-`로 표시됩니다. |
| **대기 사유** | 자원 할당 대기 원인 안내 (*GPU 여유 용량 부족*, *호스트 여유 부족*(노드 CPU/메모리 부족), *CPU 노드 없음* 등). |
| **요청 자원** | 할당 대기 중인 GPU 모델, VRAM, GPU 코어 수량입니다. |
| **대기 시작** | 대기열 진입 시각입니다. |

대기열 페이지는 5초 간격으로 자동 갱신됩니다.

![대기 중인 세션](/img/screens/session-queued.png)

개별 세션 상세 페이지에서도 동일한 대기 상태 및 사유를 조회할 수 있으며, [이벤트 로그](./sessions-manage.md#이벤트-로그)에 기록되어 총 대기 시간을 확인할 수 있습니다.

## 대기열 처리 순서

기존 세션 종료, 일시정지, 또는 노드 자원 확보 시 대기 세션이 **우선순위(Priority)** 순으로 자동 승인 및 실행됩니다. 동일한 우선순위 내에서는 대기열 진입 순서(FIFO)에 따라 처리됩니다. 우선순위 변경은 관리자 권한을 통해서만 가능합니다.

사용자별 [자원 정책](../admin/resources.md)에 따라 동시에 등록할 수 있는 최대 대기 세션 수(기본 설정: 2개)가 제한될 수 있습니다.

## 대기 중 유의 사항

- **대기 중 크레딧 미차감:** 세션 생성 시 지정된 크레딧 금액은 선예약 상태로 유지되며, 컨테이너가 실제 **실행 중** 상태로 전환되기 전까지는 크레딧이 차감되지 않습니다.
- **작은 티어 변경 시 빠른 실행 가능:** *GPU 여유 용량 부족* 사유로 대기 중인 경우, 한 단계 낮은 GPU 티어로 세션을 재생성하면 대기 없이 즉시 시작될 가능성이 높습니다.
- **CPU 세션 대기 미발생:** GPU 자원이 필요 없는 데이터 전처리 등의 작업은 무료 CPU 세션을 활용하면 대기 없이 바로 실행할 수 있습니다.

## 대기 취소

![대기 취소](/img/screens/queue-cancel-confirm.png)

**대기 취소** 버튼을 클릭하면 대기열에서 해당 항목이 삭제되고 세션이 취소됩니다. 선예약된 크레딧 금액은 전액 환불/해제되며, 실행되지 않은 대기 세션에 대해서는 과금이 발생하지 않습니다. 단, 취소 후 재요청 시 대기 순번은 맨 뒤로 재할당됩니다.
