# 대기열에서 기다리기

요청한 GPU에 빈 자리가 없어도 세션은 **거부되지 않습니다**. 대기열에 들어가 자리가 나면 스스로
시작합니다. 탭을 닫아도 됩니다.

![대기열](/img/screens/queue.png)

## 대기열이 알려 주는 것

| 열 | 의미 |
|---|---|
| **세션** | 기다리는 세션. 눌러 상세로 갑니다. |
| **위치** | 몇 번째인지. #1이 다음 차례입니다. |
| **예상 대기** | 추정할 이력이 쌓이면 표시되고, 그전에는 `-`입니다. |
| **대기 사유** | 왜 기다리는지 — *GPU 여유 용량 부족*, *호스트 여유 부족*(카드가 아니라 노드의 CPU·메모리), *CPU 노드 없음*. |
| **요청 자원** | 자리를 잡아 둔 모델, VRAM, 코어. |
| **대기 시작** | 들어온 시각. |

페이지는 5초마다 스스로 새로고침합니다.

![대기 중인 세션](/img/screens/session-queued.png)

세션 자체 페이지도 상태 줄에 같은 내용을 보여 주고
[이벤트 로그](./sessions-manage.md#이벤트-로그)에 사유를 남기므로, 나중에 얼마나 기다렸는지 확인할
수 있습니다.

## 순서는 어떻게 정해지나

자원이 돌아올 때마다 — 세션이 끝나거나, 일시정지되거나, 관리자가 노드를 비울 때 — 대기 세션이
**우선순위 순**으로, 같은 우선순위 안에서는 들어온 순서로 승인됩니다. 관리자는 항목의 우선순위를
올릴 수 있지만 본인이 직접 올릴 수는 없습니다.

[자원 정책](../admin/resources.md)은 동시에 대기시킬 수 있는 개수도 제한합니다(기본 카탈로그는 3개).

## 기다리는 동안

- **크레딧은 예약될 뿐 소비되지 않습니다.** 예약은 세션을 만들 때 잡혔고, 컨테이너가 실제로 돌기
  전까지는 아무것도 소비되지 않습니다.
- **더 작은 티어는 대개 즉시 시작됩니다.** *GPU 여유 용량 부족*으로 기다리는 경우, 한 단계 작은
  조각이면 바로 풀리는 일이 많습니다. 작업이 들어간다면 취소하고 다시 만드세요.
- **CPU 세션은 GPU 때문에 기다리지 않습니다.** 전처리 작업이라면 무료 CPU 세션이 지금 바로 돕니다.

## 취소

![대기 취소](/img/screens/queue-cancel-confirm.png)

**대기 취소**는 항목을 지우고 기다리던 세션을 종료합니다. 예약은 전액 해제됩니다. 한 번도 돌지 않은
세션에는 과금하지 않습니다. 순번은 잃습니다. 다시 요청하면 맨 뒤부터입니다.
