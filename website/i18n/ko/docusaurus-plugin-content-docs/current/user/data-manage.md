# 용량 변경, 잠금, 삭제

## 쿼터 변경 {#쿼터-변경}

![쿼터 변경](/img/screens/data-quota.png)

**쿼터 변경**은 볼륨이 담을 수 있는 용량을 올립니다. 대화 상자가 현재 쿼터와 사용량을 보여 주고,
새 값은 세 가지 조건을 통과해야 합니다.

- **저장된 양보다 작으면 안 됩니다** — 이미 들어 있는 데이터가 있으므로 축소는 거부됩니다.
- **정책의 스토리지 한도 안** — 내 모든 볼륨 합계 기준.
- **스토리지 서버에 실제로 남은 용량 안**.

변경은 살아 있는 볼륨에 바로 적용됩니다. 그 볼륨을 마운트한 세션은 재시작 없이 새 용량을 봅니다.

정책의 스토리지 한도가 걸림돌이라면 데이터를 지우기 전에
[마이페이지 → 내 한도](./account-limits.md)에서 증액을 요청하세요.

## 잠금

![잠긴 볼륨](/img/screens/data-locked.png)

**잠금**은 *새* 마운트를 막습니다. 이미 열어 둔 세션은 계속 동작합니다.

두 가지 용도가 있습니다.

- **삭제 전에** — 안을 확인하는 동안 누군가 새 세션으로 붙지 않도록 잠가 둡니다.
- **정리하는 동안** — 읽고 있는 작업 밑에서 파일을 옮기면 디버그하기 어려운 버그가 됩니다.

**잠금 해제**로 되돌립니다. 그전까지 목록에 **잠김** 태그가 붙습니다.

## 삭제

![삭제 확인](/img/screens/data-delete-confirm.png)

**삭제**는 무엇을 잃는지 — 저장된 데이터 — 를 알려 주며 확인을 요구합니다.
**활성 마운트가 없어야** 합니다. 있으면 거부되고,
[펼친 행](./data-mount.md#지금-누가-쓰고-있나)이 어느 세션을 먼저 끝내야 하는지 알려 줍니다.

그다음:

1. 볼륨이 즉시 목록에서 사라지고 쿼터도 정책 한도에서 빠집니다.
2. 실제 스토리지는 사이트가 정한 짧은 유예 기간(기본 24시간) 동안 보관된 뒤 완전히 회수됩니다.

그 안에는 관리자가 복구할 수 있고, 지나면 아무도 복구할 수 없습니다.

:::caution 콘솔에는 실행 취소가 없습니다
확인 창이 마지막 관문입니다. 확신이 없는 것은 다른 볼륨에 먼저 복사하세요. 볼륨은 쿼터 외에 비용이
들지 않습니다.
:::

## 도움이 되는 습관

- 실험이 끝나면 임시 볼륨을 지우세요. 스토리지 한도가 차는 가장 흔한 이유입니다.
- 데이터셋은 읽기전용으로 두고 사람마다 복사하는 대신 공유하세요. 100 GiB 하나가 다섯 개보다
  낫습니다.
- 목록의 **쿼터** 열을 가끔 보세요. 게이지가 95%인 볼륨은 작업이 `No space left on device`로
  실패하기 한참 전에 눈에 띕니다.
