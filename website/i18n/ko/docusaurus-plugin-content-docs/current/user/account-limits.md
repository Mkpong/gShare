# 내 한도

실행 가능한 수량을 제한하는 요인은 **크레딧**(비용, [지갑](./wallet.md))과 **쿼터**(자원 정책) 두 가지입니다. 이 페이지에서는 **쿼터**에 대해 설명합니다.

![적용 중인 자원 정책](/img/screens/account-limits.png)

## 나에게 적용 중인 정책

카드에는 이미 계산이 완료된 유효 한도가 표시됩니다. 자원 정책은 사용자별·부서별·조직별·전역 단위로 설정할 수 있으며 **항목별로** 적용됩니다. 각 한도에는 가장 구체적인 범위의 정책이 우선 적용되며, 설정값이 비어 있으면 다음 상위 범위의 정책을 따릅니다. 화면에는 내부 후보 정책이 아닌 최종 결과만 표시됩니다.

| 한도 항목 | 제한 내용 |
|---|---|
| **동시 실행 세션** | 실행·일시정지·대기 중인 세션의 총개수 |
| **대기 세션** | 동시에 대기시킬 수 있는 세션 개수 |
| **VRAM** / **GPU 코어** | 내 모든 GPU 세션의 자원 합계 |
| **CPU** / **메모리** / **디스크** | 내 모든 세션의 호스트 자원 합계 |
| **스토리지** | 내 모든 [볼륨](./data.md)의 쿼터 합계 |
| **최대 실행 시간** | 이 시간을 초과하면 세션이 자동 종료됩니다 |
| **유휴 시간** | 지정된 시간 동안 요청이 없으면 GPU 세션이 일시정지되고 자원이 반환됩니다 |
| **CPU 세션 한도** | 무료 CPU 세션에 별도로 적용되는 동일한 종류의 한도 |

비어 있는 항목은 **무제한**으로 적용됩니다.

동일한 수치를 '한도'가 아닌 '잔여량'으로 보여주는 곳은 [대시보드](./dashboard.md#자원-할당량)와 [세션 마법사](./sessions-create.md#시작-전-확인-사항-내-한도) 상단입니다. 선택할 수 없는 티어가 해당 위치에 표시되므로, 실제 쿼터 부족 여부를 여기서 확인할 수 있습니다.

## 증액 요청 {#증액-요청}

**자원 증액 요청**(이 페이지, 대시보드, 지갑 메뉴에 위치)을 클릭하면 항목별 입력 칸이 있는 신청 폼이 열립니다. 변경을 원하는 항목**만** 작성하면 되며, 각 칸에는 현재 한도 값이 함께 표시됩니다. 신청 사유 작성은 필수입니다.

![요청 내역](/img/screens/account-quota-history.png)

하단 내역에서 요청의 처리 진행 상황을 확인할 수 있습니다.

| 상태 | 의미 |
|---|---|
| **대기** | 관리자의 승인을 기다리는 중 |
| **승인** | 새 한도가 적용 완료됨 (이 페이지의 한도 수치가 업데이트됨) |
| **반려** | 거절됨 (거절 사유가 함께 표시됨) |

## 오류 메시지별 원인 및 해결 방법

| 메시지 | 원인 | 해결 방법 |
|---|---|---|
| *쿼터 초과* | 자원 정책 한도 초과 (VRAM, CPU, 스토리지 등) | 이 페이지에서 증액 요청 |
| *동시 실행 한도* | 실행 중인 세션 수가 너무 많음 | 세션 종료/일시정지 또는 증액 요청 |
| *크레딧 부족* | 계정 잔액 부족 (쿼터가 아닌 비용 문제) | [크레딧 요청](./wallet-request.md) |
| *GPU 여유 용량 부족* | 클러스터 자원 고갈 (사용자 개인 한도와 무관) | [대기열](./sessions-queue.md)에서 대기하거나 더 작은 티어 선택 |
