# 내 한도

실행할 수 있는 양을 제한하는 것은 두 가지입니다. **크레딧**(돈, [지갑](./wallet.md))과
**쿼터**(자원, 정책). 이 페이지는 두 번째 이야기입니다.

![적용 중인 자원 정책](/img/screens/account-limits.png)

## 나에게 적용 중인 정책

카드에는 이미 계산이 끝난 유효 한도가 나열됩니다. 정책은 사용자별·부서별·조직별·전역으로 둘 수
있고 **항목별로** 적용됩니다. 한도마다 그 값을 정한 가장 구체적인 정책이 이기고, 비어 있으면 다음
범위로 넘어갑니다. 후보 네 개가 아니라 결과만 보입니다.

| 한도 | 무엇을 제한하나 |
|---|---|
| **동시 실행 세션** | 실행·일시정지·대기 중인 세션의 합 |
| **대기 세션** | 동시에 대기시킬 수 있는 개수 |
| **VRAM** / **GPU 코어** | 내 모든 GPU 세션의 합계 |
| **CPU** / **메모리** / **디스크** | 내 모든 세션의 호스트 자원 합계 |
| **스토리지** | 내 모든 [볼륨](./data.md)의 쿼터 합계 |
| **최대 실행 시간** | 이 시간을 넘으면 세션이 자동 종료됩니다 |
| **유휴 시간** | 이만큼 놀면 GPU 세션이 일시정지되고 카드가 반환됩니다 |
| **CPU 세션 한도** | 무료 CPU 세션에 따로 적용되는 같은 종류의 한도 |

비어 있는 항목은 **무제한**입니다.

같은 수치를 한도가 아니라 잔여로 보여 주는 곳이 [대시보드](./dashboard.md#자원-할당량)와
[세션 마법사](./sessions-create.md#시작-전에-내-한도) 상단입니다. 살 수 없는 티어가 거기서
표시되므로 실제로 눈치채는 곳도 거기입니다.

## 증액 요청 {#증액-요청}

**자원 증액 요청**(이 페이지, 대시보드, 지갑에 있습니다)은 한도마다 입력칸 하나씩인 폼을 엽니다.
올리고 싶은 항목**만** 채우면 되고, 각 칸에는 현재 값이 함께 표시됩니다. 사유는 필수입니다.

![요청 내역](/img/screens/account-quota-history.png)

아래 내역이 요청의 진행을 추적합니다.

| 상태 | 의미 |
|---|---|
| **대기** | 관리자의 처리를 기다리는 중 |
| **승인** | 새 한도가 이미 적용되었습니다 — 이 페이지의 수치가 올라가 있습니다 |
| **반려** | 거절됨. 사유가 함께 표시됩니다 |

## 어떤 오류가 어떤 한도인가

| 메시지 | 원인 | 해결 |
|---|---|---|
| *쿼터 초과* | 정책 한도 — VRAM, CPU, 스토리지 | 여기서 증액 요청 |
| *동시 실행 한도* | 세션이 너무 많음 | 하나 끝내거나 일시정지, 또는 증액 요청 |
| *크레딧 부족* | 쿼터가 아니라 돈 | [크레딧 요청](./wallet-request.md) |
| *GPU 여유 용량 부족* | 클러스터가 꽉 참. 내 한도와 무관 | [대기열](./sessions-queue.md)에서 기다리거나 작은 티어 선택 |
