# 크레딧 요청

잔액이 부족하면 부서에 요청합니다. **크레딧 요청**은 지갑 페이지와 대시보드에 있습니다.

![크레딧 요청](/img/screens/wallet-request.png)

## 요청 보내기

폼 상단에 **요청 대상** — 내 부서의 관리자 — 이 표시되고, 두 가지를 묻습니다.

- **요청 크레딧** — 크레딧 단위 금액.
- **사유** — 관리자에게 금액과 함께 표시됩니다. "크레딧이 더 필요합니다"보다
  "ImageNet 파인튜닝, GPU 40시간 정도"처럼 구체적인 쪽이 빨리 승인됩니다.

금액을 가늠하는 방법: 세션 마법사가 만들려는 구성의 시간당 크레딧을 보여 줍니다. 필요한 시간을
곱하고 실패하는 실행분을 조금 더하세요.

## 진행 확인

![크레딧 요청 탭](/img/screens/wallet-requests.png)

**크레딧 요청** 탭에 요청과 상태가 나열됩니다.

| 상태 | 의미 |
|---|---|
| **대기** | 관리자의 처리를 기다리는 중 |
| **승인** | 크레딧이 이미 지갑에 들어왔습니다 — [거래 내역](./wallet-ledger.md)에 배분 행이 있습니다 |
| **반려** | 거절됨. 관리자의 사유가 함께 표시됩니다 |

어느 쪽이든 알림을 받고, 종 아이콘에 기록이 남습니다
([알림](./account-notifications.md) 참고).

## 크레딧이 아니라 자원이 부족할 때

한도는 크레딧만이 아닙니다. 세션이 **쿼터** 때문에 거부된다면 — 동시 실행 수, VRAM, 스토리지 —
크레딧을 더 받아도 소용없습니다. 그것은 [자원 정책](./account-limits.md)의 문제이고, 콘솔에는 바로
옆에 **자원 증액 요청** 버튼이 따로 있습니다.

기준은 이렇습니다.

| 증상 | 요청할 것 |
|---|---|
| GPU 세션 시작 시 *크레딧 부족* | 크레딧 |
| *쿼터 초과*, *동시 실행 한도*, 스토리지 가득 참 | [자원 증액](./account-limits.md#증액-요청) |
| 세션이 오래 대기함 | 둘 다 아님 — 클러스터가 붐비는 것입니다. [대기열](./sessions-queue.md) 참고 |
