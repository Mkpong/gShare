# 세션에서 볼륨 쓰기

볼륨은 세션 안에서만 접근할 수 있습니다. 세션을 만들 때 고릅니다 —
[마법사](./sessions-create.md#4단계--볼륨) 4단계입니다.

![볼륨 마운트](/img/screens/wiz-volume-mount.png)

체크한 볼륨마다:

- **마운트 경로** — 컨테이너 안에서 보일 위치. 기본값은 `/data/<종류>`이며, 볼륨마다 다른 경로를
  주어 겹치지 않게 하세요.
- **모드** — 읽기/쓰기 또는 읽기전용. 읽기전용으로 공유받았거나 읽기전용으로 만든 볼륨은
  읽기전용으로 고정됩니다.

경로는 절대 경로, ASCII 문자(`A-Z a-z 0-9 . _ -`), 그리고 시스템 디렉터리(`/etc`, `/usr`, `/bin`,
`/proc`, `/dev` …) 밖이어야 합니다. 잘못된 경로는 타이핑하는 동안 바로 거부됩니다.

## 세션 안에서

```bash
ls /data/imagenet        # 지정한 경로의 볼륨
df -h /data/imagenet     # 스토리지 서버 전체가 아니라 쿼터가 보입니다
```

쿼터는 스토리지 계층이 강제합니다. 넘겨 쓰면 `No space left on device`로 실패하고, 다른 볼륨에는
영향이 없습니다.

마운트 경로 **바깥**의 모든 것 — 홈 디렉터리, `/tmp`, 설치한 패키지 — 은 컨테이너 임시 디스크에
있고 세션이 끝나면 사라집니다. JupyterLab 기본 폴더에 저장한 노트북도 옮기지 않았다면 임시
디스크입니다.

## 같은 볼륨을 두 세션에서

읽기/쓰기 볼륨은 여러 세션이 동시에 마운트할 수 있습니다(RWX 스토리지입니다). 한 세션은 전처리하고
다른 세션은 학습하는 식으로 쓸모가 있지만, gShare가 쓰기를 조율하지는 않습니다. 두 세션이 같은
파일을 쓰는 것은 사용자의 책임입니다.

흔한 안전한 방식은 **쓰기 하나, 읽기 여럿**입니다. 데이터셋을 만드는 세션에서만 읽기/쓰기로
마운트하고 나머지는 읽기전용으로 두세요.

## 지금 누가 쓰고 있나 {#지금-누가-쓰고-있나}

목록에서 볼륨을 누르면 펼쳐집니다.

![볼륨을 마운트한 세션](/img/screens/data-mounts.png)

먼저 **데이터가 있는 곳** — 볼륨이 만들어진 스토리지 서버, 아직 아무것도 마운트하지 않았다면 *아직
미생성* — 이 보이고, 그 아래에 **지금** 그 볼륨을 쥐고 있는 세션이 소유자·마운트 모드와 함께
나열됩니다. 삭제가 거부될 때 답이
되는 곳이기도 합니다. 활성 마운트가 있는 볼륨은 삭제할 수 없고, 어느 세션을 먼저 끝내야 하는지
여기서 알 수 있습니다.

## 실행 중 세션의 마운트 바꾸기

바꿀 수 없습니다. 마운트는 세션을 만들 때 고정됩니다. 세션을 끝내고 원하는 마운트로 새로
만드세요. 데이터는 그대로입니다. 데이터는 세션이 아니라 볼륨의 것입니다.
