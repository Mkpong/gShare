# 세션 내 볼륨 사용하기

볼륨은 세션 내부에서만 접근 가능하며, 세션 생성 시 마운트할 볼륨을 지정합니다 ([세션 생성 마법사](./sessions-create.md#4단계--볼륨) 4단계).

![볼륨 마운트](/img/screens/wiz-volume-mount.png)

마운트할 볼륨별 설정 항목:

- **마운트 경로:** 컨테이너 내부에서 연결될 디렉터리 경로입니다. 기본값은 `/data/<종류>`이며, 볼륨 간 경로가 중복되지 않도록 개별 설정하세요.
- **모드:** 읽기/쓰기(RWX) 또는 읽기 전용(ROX)을 선택합니다. 읽기 전용으로 공유되었거나 읽기 전용으로 생성된 볼륨은 읽기 전용 모드로 고정됩니다.

마운트 경로는 절대 경로여야 하며, 영문 대소문자·숫자·특수문자(`.`, `_`, `-`)만 사용할 수 있습니다. 또한 주요 시스템 디렉터리(`/etc`, `/usr`, `/bin`, `/proc`, `/dev` 등) 하위 경로는 지정할 수 없으며, 유효하지 않은 경로는 입력 시 즉시 제한됩니다.

## 세션 내부에서 볼륨 확인

```bash
ls /data/imagenet        # 마운트된 볼륨 디렉터리 확인
df -h /data/imagenet     # 할당된 볼륨 쿼터 용량 확인
```

볼륨 쿼터는 스토리지 시스템에 의해 엄격히 적용됩니다. 할당된 용량을 초과하여 데이터를 저장하면 `No space left on device` 오류가 발생하며, 이는 해당 볼륨 외 다른 영역에는 영향을 주지 않습니다.

마운트 경로 **외**의 모든 영역(홈 디렉터리, `/tmp`, 추가 설치 패키지 등)은 세션 컨테이너의 임시 디스크에 저장되며, 세션 종료 시 완전히 삭제됩니다. JupyterLab 기본 디렉터리에 작성한 노트북 파일 역시 볼륨으로 이동하지 않으면 세션 종료 시 유실됩니다.

## 동일 볼륨의 다중 세션 마운트

읽기/쓰기 모드 볼륨은 여러 세션에서 동시에 마운트할 수 있습니다 (RWX 스토리지 지원). 예를 들어 한 세션에서는 데이터 전처리를 진행하고 다른 세션에서는 모델 학습을 동시에 수행할 수 있습니다. 단, 플랫폼 차원의 동시 쓰기 제어(Locking)는 제공되지 않으므로, 동일 파일에 대한 동시 쓰기 작업 시 데이터 충돌이 발생하지 않도록 주의해야 합니다.

안전한 권장 작업 방식은 **단일 쓰기 / 다중 읽기 (1 Write, Multi Read)** 구조입니다. 데이터셋을 생성·수정하는 세션에서만 읽기/쓰기 모드로 마운트하고, 이를 참조하는 다른 세션들에서는 읽기 전용 모드로 마운트하세요.

## 볼륨 사용 현황 및 활성 마운트 확인 {#지금-누가-쓰고-있나}

볼륨 목록에서 특정 볼륨 행을 클릭하면 상세 정보가 펼쳐집니다.

![볼륨을 마운트한 세션](/img/screens/data-mounts.png)

상세 정보에서는 해당 볼륨이 위치한 **스토리지 서버** 정보(최초 마운트 전에는 *미생성*으로 표시)와 현재 해당 볼륨을 **마운트 중인 세션 목록**(소유자, 마운트 모드 등)이 함께 표시됩니다. 활성 마운트가 존재하는 볼륨은 삭제가 불가능하므로, 삭제 거부 시 이곳에서 선행 종료가 필요한 세션을 확인할 수 있습니다.

## 실행 중인 세션의 마운트 변경

실행 중인 세션의 볼륨 마운트 설정은 변경할 수 없습니다. 마운트 정보는 세션 생성 시 고정되므로, 마운트 설정을 변경하려면 현재 세션을 종료한 후 원하는 마운트 구성을 적용하여 새 세션을 생성해야 합니다. 세션을 종료하더라도 볼륨에 저장된 데이터는 안전하게 보존됩니다.
