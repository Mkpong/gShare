# 역할과 범위

gShare는 콘솔 하나에 두 모드가 있습니다. 관리 역할이 있는 사용자는 오른쪽 위에서 **관리자 콘솔**로
전환할 수 있고, 무엇이 보이는지는 역할에 따라 정해집니다.

| 역할 | 범위 | 보통 누가 |
|---|---|---|
| **구성원(member)** | 자기 세션·볼륨·지갑 | 모든 사용자 |
| **부서 관리자(group_admin)** | 부서 하나: 구성원, 그들의 세션, 부서 크레딧 풀 | 팀 리더 |
| **조직 관리자(org_admin)** | 조직 하나: 소속된 모든 부서와 사용자, 조직 예산 | 부서장·연구실 관리자 |
| **시스템 관리자(super_admin)** | 전체와 플랫폼 자체: 조직, 오퍼링, 정책, 클러스터, 노드, 스토리지, 이미지 | 플랫폼 운영자 |

역할은 **범위가 있습니다**. *비전팀*의 부서 관리자는 *NLP팀*의 아무것도 보지 못하고, 한 조직의
조직 관리자는 다른 조직의 아무것도 보지 못합니다. 한 사람이 부서마다 다른 역할을 가질 수 있습니다.

## 역할별 권한

| 권한 | 구성원 | 부서 관리자 | 조직 관리자 | 시스템 관리자 |
|---|---|---|---|---|
| 자기 세션·볼륨·지갑 | ✅ | ✅ | ✅ | ✅ |
| 세션 관제·감사 로그 | — | 부서 | 조직 | 전체 |
| 사용자·부서 관리 | — | 부서 | 조직 | 전체 |
| 크레딧 배분 | 요청만 | 부서 → 개인 | 조직 → 부서 | 충전 및 전체 |
| 조직, 오퍼링, 정책, 클러스터, 노드, 스토리지, 이미지 | — | — | — | ✅ |

## 두 종류의 관리자

[테넌트 관리](./dashboard.md) 페이지들은 조직·부서 관리자가 매일 다루는 것입니다.
[사람](./users.md), [크레딧](./credits.md), 무엇이 [돌고 있는지](./monitoring.md),
[무슨 일이 있었는지](./audit.md). [플랫폼 관리](./resources.md) 페이지들은 시스템 관리자 전용이며
기계 쪽을 다룹니다. [GPU 카탈로그](./resources-offerings.md), [클러스터](./clusters.md)와
[노드](./nodes.md), [스토리지](./storage.md), [이미지](./images.md),
[시스템 설정](./system.md).

## 실제로는 누가 처리하나

| 상황 | 담당 |
|---|---|
| "크레딧이 더 필요해요" | 그 사용자의 부서 관리자 — [크레딧 요청](./credits-requests.md) |
| "쿼터를 올려 주세요" | 정책 주인. 부서 정책이면 부서 관리자, 전역이면 시스템 관리자 — [자원 요청](./resources-policies.md#자원-증액-요청) |
| "누가 GPU를 잡아만 두고 안 써요" | 범위 안의 아무 관리자 — [개입하기](./monitoring-control.md), 또는 유휴 시간 조정 |
| "새 사람이 왔어요" | 부서·조직 관리자 — [사용자 추가](./users-add.md) |
| "노드를 점검해야 해요" | 시스템 관리자 — [비우기](./nodes.md#비우기) |
| "스토리지 풀이 꽉 찼어요" | 시스템 관리자 — [스토리지](./storage.md) |
| "세션이 *unserviceable*로 실패해요" | 시스템 관리자 — [오퍼링](./resources-offerings.md)이 카드와 안 맞습니다 |

## 되돌릴 수 없는 작업

되돌릴 수 없는 작업 — 사용자·부서·조직·클러스터·오퍼링·프리셋·볼륨 삭제 — 은 대상의 이름을
입력하도록 요구합니다. 되돌릴 *수 있는* 작업(예: 관리자 해제)은 즉시 적용되고 몇 초 동안
**실행 취소**를 제공합니다.
