# GPU 오퍼링 카탈로그 관리

**오퍼링(Offering)**은 플랫폼 내의 GPU 모델을 세션 생성 마법사에서 사용자가 선택하고 과금할 수 있는 카탈로그 상품 형태로 정의한 단위입니다. 세션 생성 마법사는 등록된 오퍼링 카탈로그를 기반으로 구성되며, 자원 스케줄러는 오퍼링에 설정된 단가와 자원 스펙을 기준 삼아 과금을 정산합니다.

![GPU 오퍼링 목록 화면](/img/screens/admin-resources.png)

## GPU 오퍼링 목록 속성

| 테이블 항목 | 의미 및 설명 |
|---|---|
| **이름** | 사용자 콘솔 및 세션 생성 마법사에 표시되는 오퍼링 제품명 (예: `RTX 4090`) |
| **모델** | GPU 드라이버가 보고하는 정확한 디바이스 인식 문자열 (플릿에서 인식 중인 경우 `클러스터 보유` 태그 표시) |
| **VRAM · 코어** | 해당 GPU 카드 1장당 전체 VRAM 용량 및 GPU 코어 자원 |
| **클래스** | `gpu` (과금 대상 유료 오퍼링) 또는 `cpu` (무료 데이터 처리용 오퍼링) |
| **단가** | GPU 카드 1장 기준 시간당 소모 크레딧 (vGPU 분할 세션의 경우 점유 비율만큼 비례 차감) |
| **최소 CUDA** | 해당 오퍼링에서 워크로드를 실행하기 위한 최소 요구 CUDA 드라이버 버전 (미달 이미지 할당 불가) |
| **상태** | `활성` (세션 생성 마법사에 노출 및 신규 생성 가능) 및 `비활성` (신규 생성 불가, 과거 세션 이력 보존) |

## 신규 오퍼링 생성

![신규 오퍼링 등록 대화 상자](/img/screens/admin-offering-new.png)

:::caution GPU 모델 문자열 정밀 일치 필수
스케줄러의 자원 승인 로직은 `gpu_model` 값을 드라이버가 보고하는 문자열과 대소문자 및 공백을 포함해 글자 단위로 정밀 비교합니다. (예: `RTX 4090` (X) → `NVIDIA GeForce RTX 4090` (O))

오류를 방지하기 위해 임의로 직접 입력하지 말고 **[GPU 디바이스](./gpus.md)** 메뉴에서 드라이버가 인식한 실제 문자열을 복사하여 사용하세요.

만약 데이터 플레인 플릿이 상세 SKU 문자열(예: `... Max-Q Workstation Edition`)을 보고하고, 오퍼링에 등록된 접두어(Word Boundary) 문자열과 일치하는 단일 오퍼링이 존재하는 경우, 시스템이 해당 오퍼링을 자동으로 바인딩하고 감사 로그(`offering.align_model`)에 내역을 기록합니다. 그럼에도 `unserviceable` 오류로 스케줄링이 거부되는 경우, 오류 메시지 상에 출력되는 플릿의 실제 보고 모델 문자열을 복사하여 등록하세요.
:::

### 단가 산정 정책 수립 가이드

오퍼링 단가 설정은 단순 기술 수치가 아닌 플랫폼 과금 정책 결정에 해당합니다. 다음 두 가지 기준을 고려하여 단가를 산정하세요.

* **상대 단가의 합리적 설정**: 고급 카드(예: H100)의 가치가 일반 카드(예: RTX 4090) 3대의 가치에 해당한다면 해당 가치 비율을 반영하여 단가를 설정하세요. 상대 단가가 정직하게 설정되어야 사용자가 소규모 워크로드에 무분별한 고성능 카드가 아닌 합리적인 저렴한 모델을 선택하게 됩니다.
* **월간 예산과의 연동**: **[크레딧 배분](./credits-allocate.md)** 정책을 수립할 때 일반 사용자의 월평균 사용 시간이 수용 가능한 예산 범위 내에 머물도록 기준 단가를 조정하세요.

## 오퍼링 수정 및 비활성화

- **단가 수정 소급 적용 불가**: 단가 수정 내역은 **신규 생성되는 세션에만 적용**됩니다. 이미 실행 중인 세션은 시작 시점의 단가를 유지하므로, 가격 변경으로 인해 기존 구동 세션의 청구 금액이 소급 변경되지 않습니다.
- **단가 변경 이력 보존**: 단가 변경 내역은 오퍼링 가격 이력 API (`/api/v1/offerings/{id}/price-history`) 및 DB에 보존되므로, 지난 학기 또는 과거 정산 리포트의 과금 기준을 투명하게 증명할 수 있습니다.
- **오퍼링 비활성화 (Deactivate)**: 특정 GPU 모델이 물리 플릿에서 제거되더라도 오퍼링 레코드를 직접 삭제하지 말고 **비활성화** 처리하세요. 과거 세션 이력 및 과금 원장이 해당 오퍼링 ID를 참조하므로 이력 조회가 가능하도록 데이터를 유지해야 합니다.

## CPU 전용 오퍼링

`cpu` 클래스 오퍼링은 GPU 카드를 포함하지 않으며 크레딧 단가가 `0`으로 설정됩니다. 이는 데이터 사전 처리, 코드 데버깅 등 GPU 자원이 필요하지 않은 단순 컴퓨팅 세션을 제공하기 위해 활용됩니다.

CPU 전용 오퍼링은 크레딧이 소모되지 않으므로 무분별한 점유를 방지하기 위해 **[자원 정책](./resources-policies.md)**의 쿼터(Quota) 한도 설정을 통해 동시 실행 세션 및 CPU/메모리 사용량을 제한해야 합니다.
