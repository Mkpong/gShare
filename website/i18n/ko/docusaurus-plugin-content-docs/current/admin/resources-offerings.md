# GPU 오퍼링

**오퍼링**은 GPU 모델 하나를 과금 가능한 상품으로 만든 것입니다. 세션 마법사가 이 카탈로그로
만들어지고, 스케줄러가 여기에 맞춰 가격을 매깁니다.

![오퍼링](/img/screens/admin-resources.png)

| 열 | 의미 |
|---|---|
| **이름** | 사용자에게 보이는 이름. 예: *RTX 4090* |
| **모델** | 드라이버가 보고하는 정확한 모델 문자열. 플릿이 보고 중이면 **클러스터 보유** 태그 |
| **VRAM · 코어** | 카드 전체 |
| **클래스** | `gpu`(과금) 또는 `cpu`(무료 컴퓨트 오퍼링) |
| **단가** | 카드 한 장 기준 시간당 크레딧. 분할이면 그 비율만큼 |
| **최소 CUDA** | 이 버전보다 낮은 이미지는 이 모델에서 거부됩니다 |
| **상태** | 활성 오퍼링만 마법사에 나오고, 비활성은 이력용으로 남습니다 |

## 만들기

![새 오퍼링](/img/screens/admin-offering-new.png)

:::caution 모델 문자열은 정확히 일치해야 합니다
승인은 `gpu_model`을 드라이버가 보고하는 문자열과 글자 단위로 비교합니다. `RTX 4090`이 아니라
`NVIDIA GeForce RTX 4090`입니다. 타이핑하지 말고 **[GPU 디바이스](./gpus.md)에서 복사**하세요.

플릿이 더 긴 SKU(`… Max-Q Workstation Edition`)를 보고하고 그 접두어(단어 경계)인 오퍼링이 정확히
하나면, 그 오퍼링이 보고된 문자열을 자동으로 받아들이고 `offering.align_model`로 감사에 남습니다.
그래도 `unserviceable`로 거부되면, 오류가 플릿이 실제로 보고하는 모델 목록을 알려 줍니다. 그중
하나를 복사해 넣으세요.
:::

**단가** 설정은 기술이 아니라 정책 결정입니다. 기준 두 가지:

- *상대* 단가를 정직하게 두세요. 사용자에게 H100이 4090 세 장의 값어치라면 그렇게 매겨야, 작은
  작업에는 싼 카드가 자연스러운 기본값이 됩니다.
- 월 [크레딧 예산](./credits-allocate.md)을 정할 때, 보통 사용자의 보통 한 달이 의도한 만큼 들도록
  맞추세요. 절대 숫자는 그 기준에서만 의미가 있습니다.

## 수정과 폐기

단가 수정은 **새 세션에만** 적용됩니다. 실행 중 세션은 시작 시점의 단가를 그대로 유지하므로, 가격
변경이 남의 청구서를 소급해 바꾸지 않습니다.

단가 변경은 오퍼링의 가격 이력(`/api/v1/offerings/{id}/price-history`)에 모두 남으므로, 지난 학기의
청구서는 언제든 설명할 수 있습니다.

모델이 플릿에서 빠질 때는 삭제보다 비활성화를 쓰세요. 세션과 원장 행이 오퍼링을 참조하므로 이력이
읽히는 상태로 남습니다.

## CPU 오퍼링

`cpu` 클래스 오퍼링은 GPU가 없고 단가가 0입니다. 무료 데이터 준비 세션을 가능하게 하는 장치입니다.
가격이 아니라 [정책](./resources-policies.md) 한도로 제한하세요.
