# 세션 개입 및 제어 (Intervention)

본 문서에서 다루는 제어 기능들은 **타 사용자가 구동 중인 세션 워크로드에 직접 관여**하는 작업입니다. 관리자에 의한 모든 개입 작업은 해당 관리자의 계정 정보와 함께 감사 로그에 영구 기록되며, 세션 소유자에게 작업 알림이 발송됩니다.

---

## 단일 세션 강제 종료

![세션 강제 종료](/img/screens/admin-monitor.png)

세션 관제 목록 행의 **강제 종료** 기능은 세션 소유자의 명시적 동의 없이 실행 중인 세션을 즉시 중단시킵니다.

1. **자원 반환**: 세션 컨테이너가 중지되며, 점유 중이던 GPU 및 Compute 자원이 자원 풀로 즉시 반환됩니다.
2. **크레딧 정산**: 사용자가 직접 세션을 종료한 것과 동일하게 정산됩니다. 실제 사용한 시간만큼 크레딧이 차감 청구되며, 남아 있는 미사용 예약 크레딧은 개인 지갑으로 환불됩니다.
3. **알림 및 감사 기록**: 세션 소유자에게 강제 종료 알림이 전송되며, 관리자가 입력한 **종료 사유**는 세션 ID와 함께 **[감사 로그](./audit.md)**에 기록됩니다.

강제 종료된 세션의 `status_reason` 메타데이터에는 `admin_stopped` 코드가 기록되며, 사용자 콘솔 UI 상에 관리자가 작성한 사유 메시지가 노출됩니다.

> **종료 사유 작성 가이드**: 단순한 "시스템 정리" 등의 추상적 문구 대신, 사용자 또는 타 관리자가 상황을 명확히 이해할 수 있는 구체적 사유(예: *"14시 정기 실습 수업을 위한 RTX 4090 자원 확보"*)를 작성하는 것을 권장합니다.

## 일괄 세션 정리 (Bulk Actions)

관제 목록에서 복수 개의 세션 행을 체크박스로 선택하면 상단 툴바의 **강제 종료 (N)** 및 **일괄 정리 (N)** 버튼이 활성화됩니다.

* **확인 대화 상자**: 종료 대상 세션의 전체 목록과 소유자 정보가 명시됩니다.
* **안전 검증 절차**: 선택된 세션이 5개 이상인 경우, 오작동 및 실수에 의한 중단을 방지하기 위해 **대상 건수(숫자)를 직접 입력**해야만 최종 실행 버튼이 활성화됩니다.

## 대기열 관리 (Queue Management)

![대기열 관리 탭](/img/screens/admin-monitor-queue.png)

**대기열** 탭에서는 클러스터 자원 부족으로 할당 대기 중인 세션들의 순번, 설정된 우선순위, 대기 사유, 요청 자원 스펙을 통합 조회할 수 있습니다.

| 관리 제어 항목 | 동작 및 적용 영향 |
|---|---|
| **우선순위 변경** | 대기 항목의 우선순위(Priority) 정수값을 수정합니다. (높은 정수값일수록 대기열에서 먼저 스케줄링 배치됨 - 시연, 마감 임박, 정기 수업용) |
| **대기 세션 취소** | 대기열 탭 내에는 별도의 취소 버튼이 존재하지 않습니다. 대기 세션을 취소하려면 세션 관제 탭에서 해당 세션을 **강제 종료** 처리하세요. (실행 이력이 없는 대기 세션은 예약 크레딧이 전액 해제되며 과금되지 않음) |

> **대기열 운영 가이드**: 자원 고갈 시 가장 바람직한 제어 방식은 대기 세션의 **우선순위 조절**입니다. 타 사용자의 실행 중 세션을 강제 종료하여 대기 세션을 시작시키는 조치는 기존 워크로드를 파괴할 수 있으므로 명확한 사유를 감사 로그에 남기고 신중히 실행하세요.

## 강제 종료 실행 전 확인 사항

세션을 강제 종료하기 전, 해당 상황이 실제 관리자 개입이 필요한 상태인지 아래 유형을 먼저 확인하세요.

| 발생 증상 | 원인 분석 및 추천 조치 사항 |
|---|---|
| 세션이 장시간 **대기(Pending)** 상태 유지 | 시스템 장애가 아닌 자원 부족에 따른 대기열 진입 상태입니다. 대기 사유 메트릭을 먼저 확인하세요. |
| **실행 중(Running)** 상태이나 GPU 사용률 0% | 작업이 일시 중단되었거나 유휴 상태인 워크로드입니다. 유휴 자동 제어 정책에 의해 자동 일시 중지 처리되므로, 필요 시 **[자원 정책](./resources-policies.md)**의 유휴 감지 시간을 조정하세요. |
| 세션이 계속해서 **재시작(CrashLoop)**을 반복 | 플랫폼의 크래시 루프 감지 규칙에 의해 수 분 내에 자동 중단 및 정산 처리됩니다. |
| 특정 노드의 세션들을 타 노드로 이동시켜야 함 | **[노드 비우기(Drain)](./nodes.md#비우기)** 기능을 활용하세요. 세션을 강제 종료하지 않고 타 노드로 안전하게 재배치(Evict)합니다. |

> **권장 사항**: 노드 점검이나 자원 확보 시 세션을 강제 종료하는 것보다 **[노드 비우기(Drain)](./nodes.md#비우기)** 기능을 사용하는 것이 권장됩니다. 워크로드 데이터를 파괴하지 않고 안전하게 다른 노드로 이전시킬 수 있습니다.
