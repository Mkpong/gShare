# 노드 풀

**풀**은 클러스터 안 노드의 이름 붙인 묶음입니다. 자기 기계를 사 온 부서가 별도 플랫폼을 돌리지
않고도 그 기계에 우선권을 갖게 하는 방법입니다.

![노드 풀](/img/screens/admin-node-pools.png)

| 종류 | 배치될 수 있는 대상 |
|---|---|
| **전용** | 명시적으로 권한을 받은 조직·부서만 |
| **공용** | 전체 |
| *(미배정)* | 어느 풀에도 없는 노드는 공용처럼 동작 |

배치는 **부서 권한 → 조직 권한 → 공용** 순으로 시도합니다. CPU 전용 세션은 풀과 무관합니다.

## 풀 만들고 채우기

![새 풀](/img/screens/admin-node-pool-new.png)

1. **새 풀** — 이름, 클러스터, 종류(전용 또는 공용), 설명.
2. **권한 추가** — 이 풀을 쓸 조직 또는 부서.
   ![권한 부여](/img/screens/admin-node-pool-grant.png)
3. **노드 탭** — 각 노드의 **목표 풀**을 지정합니다. 변경은 예약됩니다. 카드가 새 세션을 받지 않다가
   비워지면 새 풀로 옮겨지므로, 실행 중인 것은 방해받지 않습니다.

## 회수와 삭제

권한을 **회수**하면 그 테넌트의 *새* 세션이 이 풀에 오지 않습니다. 실행 중인 것은 유지됩니다.

풀을 **삭제**하면 노드는 공용으로 돌아가고 모든 권한이 사라집니다. 풀의 노드에 실행 중인 세션이
있으면 거부됩니다. 먼저 노드를 차단하세요.

## 넘침(spill) 문제

전용 풀이 꽉 찬 테넌트는 **[정책](./resources-policies.md)이 공용 풀을 허용할 때만** 공용 노드로
넘어갑니다. 이 스위치가 설계 결정의 핵심입니다.

- **넘침 허용** — 부서는 항상 자기 카드를 먼저 쓰되, 놀고 있는 공용 용량을 빌릴 수 있습니다.
  가동률이 가장 좋습니다.
- **넘침 금지** — 부서는 자기 하드웨어로 엄격히 제한됩니다. 나머지 사람들에게 예측 가능하고, 부서의
  대기열은 온전히 부서가 관리합니다.

어느 쪽을 고르든 명시적으로 알리세요. 다른 곳 카드가 노는데 자기 세션이 대기하는 사용자는 그것을
버그로 신고할 것입니다.
