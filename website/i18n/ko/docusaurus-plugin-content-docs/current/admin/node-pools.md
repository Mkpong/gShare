# 노드 풀 관리 (Node Pools)

**노드 풀(Node Pool)**은 클러스터 내 물리 노드들을 논리적으로 그룹화하여 특정 조직이나 부서에 우선적 또는 전용으로 자원을 할당하는 기능입니다. 자체 예산으로 장비를 도입한 부서가 별도의 독자적인 플랫폼을 구축하지 않고도 해당 자원에 대한 전용 접근 권한을 확보할 수 있도록 지원합니다.

![노드 풀 목록 화면](/img/screens/admin-node-pools.png)

## 노드 풀 유형 및 스케줄링 순서

| 풀 유형 | 자원 배치 대상 및 설명 |
|---|---|
| **전용 (Dedicated)** | 명시적으로 접근 권한을 부여받은 특정 조직 또는 부서 구성원만 사용 가능 |
| **공용 (Shared)** | 플랫폼 내 모든 사용자가 제약 없이 이용 가능 |
| **미배정 (Unassigned)** | 어느 풀에도 속하지 않은 노드로, 공용(Shared) 풀과 동일하게 동작 |

* **자원 배치 시도 순서**: 워크로드 생성 시 **부서 전용 풀 → 조직 전용 풀 → 공용 풀** 순서로 적합한 자원 배치를 시도합니다.
* **CPU 전용 워크로드**: CPU 전용 세션은 노드 풀 지정 및 제약 조건의 영향을 받지 않습니다.

---

## 노드 풀 생성 및 노드 할당 절차

![신규 노드 풀 생성](/img/screens/admin-node-pool-new.png)

1. **신규 풀 생성**: 풀 명칭, 대상 클러스터, 풀 유형(전용 또는 공용), 상세 설명을 입력합니다.
2. **접근 권한 부여**: 해당 전용 풀을 사용할 조직 또는 부서를 선택하여 권한을 부여합니다.
   ![노드 풀 권한 부여](/img/screens/admin-node-pool-grant.png)
3. **노드 바인딩 (목표 풀 지정)**: **노드 관리** 메뉴에서 각 노드의 **목표 풀(Target Pool)**을 지정합니다.
   * **전환 예약 (Pending Switch)**: 목표 풀 변경은 즉시 가동 중인 세션을 중단시키지 않고 예약 처리됩니다. 해당 노드에 신규 세션 할당이 중지되고, 기존 세션이 모두 종료되어 노드가 비워지면 안전하게 새 풀로 이전됩니다.

---

## 권한 회수 및 풀 삭제

* **권한 회수 (Revoke Access)**: 해당 테넌트의 신규 세션이 이 풀에 스케줄링되는 것을 차단합니다. 이미 구동 중인 기존 세션은 유지됩니다.
* **노드 풀 삭제 (Delete Pool)**: 풀을 삭제하면 소속된 노드들은 모두 공용(Shared) 풀 상태로 환원되며 설정된 모든 권한이 제거됩니다.
  * **삭제 제약 조건**: 소속 노드에 실행 중인 세션이 하나라도 남아있는 경우 삭제가 거부됩니다. 삭제 전 해당 노드들을 **차단(Cordon)** 처리하고 실행 중인 세션을 먼저 정리해야 합니다.

## 전용 자원 고갈 시 넘침(Spillover) 정책

전용 노드 풀의 자원이 모두 점유되었을 때 소속 사용자가 공용 노드 풀의 자원을 추가로 활용할 수 있는지 여부는 **[자원 정책](./resources-policies.md)**의 넘침(Spillover) 설정에 따라 결정됩니다.

* **넘침 허용 (Spillover Allowed)**: 전용 풀 자원이 다 차면 공용 풀의 남는 자원을 임시로 빌려 세션을 실행합니다. 클러스터 전체 자원 가동률을 극대화할 수 있습니다.
* **넘침 금지 (Spillover Prohibited)**: 해당 부서는 자신들에게 할당된 하드웨어 범위 내로 엄격히 제한됩니다. 타 테넌트의 공용 자원을 침범하지 않고 부서 내 대기열을 예측 가능하게 관리할 수 있습니다.

> **운영 정책 공지 가이드**: 전용 풀 자원이 고갈된 상태에서 넘침 정책이 금지되어 있으면, 공용 풀에 여유 자원이 있더라도 해당 부서 사용자의 세션은 대기(Pending) 상태로 유지됩니다. 사용자 혼선을 방지하기 위해 넘침 정책 적용 여부를 사전에 명확히 안내하세요.
