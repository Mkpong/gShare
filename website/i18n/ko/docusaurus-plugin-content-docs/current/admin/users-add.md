# 사용자 추가

인원 규모와 셀프 가입 허용 여부에 따라 세 가지 방법이 있습니다.

## 한 명씩

![새 사용자](/img/screens/admin-user-new.png)

**사용자 등록**이 묻는 것:

- **이메일** — 로그인 아이디이며 플랫폼 전체에서 고유해야 합니다.
- **이름** — 관리자와 세션 목록에 표시됩니다.
- **초기 비밀번호** — 첫 로그인에서 강제로 변경됩니다. 이후에는 아무도 볼 수 없습니다.
- **조직과 부서** — 처음부터 크레딧·정책·풀 권한이 정해집니다.

새 계정은 모두 **구성원**으로 시작합니다. 부서·조직 관리자는 나중에
[부서](./groups.md#부서-관리자) / [조직](./organizations.md#조직-관리자) 화면에서 지명합니다.

계정은 즉시 사용할 수 있습니다.

## CSV로 일괄 등록

![일괄 등록](/img/screens/admin-users-bulk.png)

**대량 등록**은 두 컬럼짜리 CSV — `email,name`(헤더 행은 자동으로 건너뜀) — 를 받아 계정을 한 번에
만듭니다. 전원이 **페이지에서 고른 조직과 부서**의 구성원이 됩니다. 수업이나 새 팀에 알맞습니다.

파일은 **무엇을 쓰기 전에 먼저 검사**합니다. 이메일 형식 오류, 파일 내 중복, 이름 없음인 행은 목록에
표시되고 제외되며 나머지는 진행합니다. 결과는 행마다 생성 / 기존 계정 / 무효로 보고되고, 이미 있는
계정은 건드리지 않습니다.

새 계정마다 초기 비밀번호가 생성됩니다. 등록이 끝날 때 자격증명 파일로 **한 번만** 내려받을 수
있습니다. 그때 저장하세요. 나중에는 다시 받을 수 없습니다.

## 셀프 가입 승인

사이트의 [가입 정책](./system.md#회원가입)이 **승인 후 사용**이면 사용자가 직접 가입할 수 있고,
목록에 **대기** 상태로 들어옵니다. 승인 전에는 로그인할 수 없습니다.

![승인 대기 계정](/img/screens/admin-users-pending.png)

![승인](/img/screens/admin-user-approve.png)

**승인**은 한 가지만 묻습니다. **어느 부서인가**. 지금 지정하는 것이 그 계정에 정책과 크레딧 풀,
노드 풀 권한을 부여합니다. 부서 없이 승인하면 로그인은 되지만 아무것도 실행할 수 없는 계정이
되고, 곧 문의가 들어옵니다.

별도의 거절 버튼은 없습니다. 가입을 거절하려면 행에서 대기 계정을 **삭제**하세요. 본인은 다시 가입할 수 있습니다.

:::tip 도메인을 제한하세요
가입 정책에는 **허용 이메일 도메인** 목록도 있습니다. 자기 도메인(`example.com`)으로 지정해 두면
엉뚱한 주소가 애초에 승인 대기열에 들어오지 않습니다. [시스템 설정](./system.md#회원가입) 참고.
:::
