# 사용자 추가 (User Onboarding)

플랫폼 운영 규모 및 가입 정책에 따라 단일 계정 수동 생성, CSV 파일 대량 등록, 승인 기반 셀프 가입(Self-Signup)의 세 가지 방식으로 신규 사용자를 추가할 수 있습니다.

---

## 단일 계정 수동 생성

![신규 사용자 등록](/img/screens/admin-user-new.png)

**사용자 등록** 대화 상자에서 다음 항목을 설정하여 계정을 생성합니다.

* **이메일 (Email)**: 사용자 로그인 ID로 활용되며, 플랫폼 전체에서 중복될 수 없는 고유값이어야 합니다.
* **이름 (Name)**: 사용자 식별을 위한 실명 또는 명칭으로 관리자 콘솔 및 세션 관제 목록에 표시됩니다.
* **초기 비밀번호 (Initial Password)**: 계정 생성 시 지정하는 일시적 비밀번호입니다. 최초 로그인 시 강제 변경 절차가 진행되며, 생성 이후에는 관리자를 포함해 누구도 조회할 수 없습니다.
* **소속 조직 및 부서 (Org & Group)**: 계정이 소속될 조직과 부서를 지정합니다. 소속 부서에 따라 초기 크레딧 풀, 자원 정책 및 전용 노드 풀 접근 권한이 자동으로 부여됩니다.

> **기본 권한**: 신규 생성된 계정은 기본 **구성원(Member)** 권한으로 등록됩니다. 부서 관리자 및 조직 관리자 권한 부여는 계정 생성 완료 후 **[부서 관리](./groups.md#부서-관리자-group-admin)** 또는 **[조직 관리](./organizations.md#조직-관리자-organization-admin)** 메뉴에서 지정하세요.

## CSV 파일 기반 대량 등록

![CSV 대량 등록](/img/screens/admin-users-bulk.png)

**대량 등록** 기능은 `email,name` 두 개의 컬럼 구조로 작성된 CSV 파일(첫 번째 헤더 행은 자동 제외)을 업로드하여 다수의 계정을 한 번에 생성합니다.

* **일괄 소속 지정**: 업로드 시 화면에서 선택한 **조직 및 부서**의 구성원으로 전원 일괄 등록됩니다. (정기 강의 수강생 온보딩이나 프로젝트 팀 일괄 생성 시 유용)
* **사전 검증 (Pre-validation)**: CSV 파일 업로드 시 계정을 생성하기 전 사전 검증을 수행합니다. 이메일 형식 오류, 파일 내부 중복, 이름 누락 행은 자동으로 걸러져 제외 목록에 표시되며, 정상 행에 대해서만 일괄 생성이 진행됩니다.
* **생성 결과 보고**: 처리 결과는 행별로 *생성 완료*, *기존 계정 존재*, *무효* 상태로 구분하여 리포트되며, 이미 존재하는 기존 계정의 정보는 변경되지 않습니다.
* **자격 증명 파일 보안**: 생성된 모든 신규 계정의 초기 비밀번호가 담긴 파일은 **등록 완료 직후 단 1회만 다운로드**할 수 있습니다. 생성 직후 파일 형태로 다운로드하여 안전하게 보관하세요. (이후 재다운로드 불가)

## 셀프 가입 승인 관리

플랫폼의 **[회원가입 정책](./system.md#회원가입)**이 *승인 후 사용(Approval Required)* 모드로 설정되어 있으면, 사용자가 직접 가입을 신청할 수 있으며 관리자 콘솔 목록에 **대기(Pending)** 상태로 포함됩니다. 관리자의 승인이 완료되기 전까지 해당 계정은 로그인이 제한됩니다.

![승인 대기 계정 목록](/img/screens/admin-users-pending.png)

![가입 승인 처리](/img/screens/admin-user-approve.png)

### 가입 승인 및 거절 절차

* **부서 지정 필수**: 승인 처리 시 해당 계정이 소속될 **부서(Group)**를 반드시 지정해야 합니다. 부서가 지정됨과 동시에 해당 계정에 적용될 자원 정책, 크레딧 풀, 노드 풀 접근 권한이 결정됩니다. (부서 미지정 상태로 승인할 경우, 로그인에는 성공하지만 실행 권한 및 자원이 부여되지 않아 오류가 발생합니다.)
* **가입 거절**: 별도의 가입 거절 버튼은 존재하지 않습니다. 가입 요청을 거절하려는 대기 상태 계정은 해당 행에서 **삭제(Delete)** 처리하세요. (삭제된 신청자는 필요 시 재가입 신청 가능)

:::tip 허용 이메일 도메인 제한
무분별한 가입 신청 및 비인가 사용자의 대기열 진입을 방지하기 위해 **허용 이메일 도메인(Allowed Domains)** 목록을 등록하는 것을 권장합니다. 소속 조직의 공식 도메인(예: `example.com`)을 등록해 두면 허용되지 않은 이메일 주소의 가입 신청이 대기열에 진입하는 것을 사전에 차단할 수 있습니다. 세부 설정법은 **[시스템 설정 → 회원가입](./system.md#회원가입)** 문서를 참조하세요.
:::
