# 이미지와 템플릿

이미지 카탈로그는 세션 마법사가 제안하는 목록입니다. 여기 없거나 선택한 카드와 호환되지 않는
이미지는 실행할 수 없습니다.

![이미지](/img/screens/admin-images.png)

| 열 | 의미 |
|---|---|
| **이름** | 사용자에게 보이는 이름 |
| **종류** | 카탈로그 이미지 또는 사용자 개인 이미지 |
| **소스** | 레지스트리 참조 |
| **CUDA** | 이미지 안의 런타임. 오퍼링의 최소 버전과 비교됩니다 |
| **지원 GPU** | 검증된 모델 |
| **공개** | 전체 공개 또는 소유자 비공개. 행에서 전환합니다 |

탭이 둘입니다. **카탈로그** 자체와 **빌드** — 콘솔에서 시작한 모든 빌드의 상태와 로그(성공 여부와
무관하게).

## 가져오기

![이미지 등록](/img/screens/admin-image-import.png)

**이미지 등록**은 레지스트리에 이미 있는 이미지를 등록합니다. 참조, 표시 이름, CUDA 버전, 대상 GPU
모델.

실제로 돌지 말지를 정하는 것은 두 가지입니다.

- **노드가 그 이미지를 받을 수 있어야** 합니다. 사설 레지스트리는 노드별 신뢰 설정이 필요하고
  ([클러스터 구축 → 로컬 레지스트리](../cluster-setup.md#local-registry-optional)), 멀티 클러스터
  플릿에서는 *모든* 클러스터가 닿아야 합니다.
- **CUDA 버전이 정직해야** 합니다. 마법사가 이 값으로 필터링합니다. 12.4로 빌드한 이미지에 12.8이라고
  적는다고 Blackwell 카드에서 돌지 않습니다. 실패가 더 늦게, 더 불분명하게 일어날 뿐입니다.

## 빌드

![이미지 빌드](/img/screens/admin-image-build.png)

**이미지 빌드**는 인라인 Dockerfile 또는 공개 git 저장소로 콘솔 주도 빌드를 시작해 결과를
`api.buildRegistry`에 푸시하고 자동으로 등록합니다.

빌드는 비동기로 진행되고 페이지가 따라갑니다:
`queued → building → pushing → scanning → succeeded`. 실패하면 로그가 남아 읽을 수 있습니다.

구성원도 자기 이미지를 빌드할 수 있습니다(1인당 최대 20개). 소유자에게만 보이고 마법사에서
**내 이미지** 태그가 붙습니다.

## 시드 이미지

`api.seedSessionImages`(기본값)이면 시작 시 CUDA 12.4/12.5 계열과 Blackwell 12.8/12.9 계열의
`boanlab/gshare-session`을 카탈로그에 시드합니다. 해당 태그는 릴리스의 퍼블리시 워크플로가 돈 뒤에야
Docker Hub에 존재합니다.

Blackwell 카드 플릿은 12.8 계열이 필요하고, 오래된 이미지는 세션 시작 전에 `incompatible_image`로
거부됩니다. 이것이 바람직한 동작입니다. 대안은 컨테이너가 뜬 뒤에 GPU를 못 보는 상황입니다.

## 카탈로그를 작게 유지하기

이미지 하나가 늘 때마다 사용자에게는 결정이 하나 늘고, 그것을 받는 모든 노드에 5–15 GiB가 쌓입니다.
프레임워크 세대마다 잘 관리된 이미지 하나가 변종 열두 개보다 낫습니다. 나머지는 각자 빌드하게
하세요.
