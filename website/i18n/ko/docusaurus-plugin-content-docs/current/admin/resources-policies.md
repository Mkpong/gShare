# 자원 정책

**정책**은 테넌트 하나가 한 번에 쥘 수 있는 양을 정합니다. 크레딧이 "살 수 있는가"를 정한다면
정책은 "살 수 있어도 가져가도 되는가"를 정합니다.

![자원 정책](/img/screens/admin-policies.png)

## 적용 순서: 가장 구체적인 것이 이깁니다

```
사용자  →  부서  →  조직  →  전역
```

적용은 **항목별**입니다. 한도마다 그 값을 정한 가장 구체적인 정책이 이기고, 어떤 정책이 비워 둔
항목은 다음 범위로 넘어갑니다. 따라서 VRAM만 정한 사용자 정책은 VRAM만 올리고, 나머지 한도는
부서·조직·전역 정책이 정한 그대로입니다. 마이페이지가 각 수치의 출처 범위를 보여 줍니다.

완전한 **전역** 정책을 바닥으로 두세요. 그 위의 정책은 실제로 바꿀 항목만 가지면 됩니다.

## 정책이 정하는 것

![새 정책](/img/screens/admin-policy-new.png)

| 항목 | 제한 대상 |
|---|---|
| **최대 동시 실행** | 실행·일시정지·대기 중인 세션의 합 |
| **최대 대기** | 동시에 기다릴 수 있는 개수 |
| **VRAM / GPU 코어** | 그 테넌트의 모든 GPU 세션 합계 |
| **CPU / 메모리 / 디스크** | 모든 세션의 호스트 자원 합계 |
| **스토리지** | 모든 볼륨의 쿼터 합계 |
| **최대 실행 시간** | 이를 넘으면 세션이 종료됩니다 |
| **유휴 시간** | 이만큼 놀면 GPU 세션이 **일시정지**되고 카드가 반환됩니다 |
| **CPU 세션 한도** | 무료 CPU 세션에 따로 적용되는 같은 한도 |
| **공용 풀 사용** | 전용 [풀](./node-pools.md)이 꽉 찼을 때 공용 노드로 넘칠 수 있는지 |
| **권한 있는 세션** | 컨테이너를 root로 실행할 수 있는지 |

비어 있으면 무제한입니다.

### 붐비는 플릿에서 가장 중요한 둘

- **유휴 시간.** 없으면 잊고 둔 노트북이 밤새 카드를 쥡니다. 1시간이 무난한 기본값이고, 사용자는
  잃는 것이 없습니다. 일시정지되었다가 재개하면 됩니다.
- **최대 동시 실행.** 한 사람이 세션 열 개를 걸어 두고 플릿을 점거하는 것을 막는 장치입니다.

## 자원 증액 요청 {#자원-증액-요청}

![들어온 요청](/img/screens/admin-quota-requests.png)

한도에 막힌 사용자는 마이페이지에서 **자원 증액 요청**을 올립니다. 요청은 여기 **요청** 탭에 올리고
싶은 항목, 현재 값, 사유와 함께 도착합니다.

**승인하면 요청된 항목만 담은 사용자 범위 정책이 작성(또는 갱신)됩니다.** 위의 항목별 적용에 따라
나머지 한도는 여전히 부서·조직·전역 정책에서 옵니다. 두 가지 습관이 이를 깔끔하게 유지합니다.

- 요청한 항목만 올려서 사용자 정책을 작고 읽기 쉽게 두세요.
- 팀 전체가 같은 문제를 겪는다면 **부서** 정책을 바꾸는 편이 낫습니다. 열 번이 아니라 한 번이고,
  아무도 기억하지 못하는 개인별 예외가 쌓이지 않습니다.

반려는 요청자에게 보이는 사유를 묻습니다. 두 결정 모두 감사에 남고 알림이 갑니다.

:::tip 크레딧인가 쿼터인가
사용자의 오류가 *크레딧 부족*이었다면 이 대기열이 아닙니다.
[크레딧 요청](./credits-requests.md)으로 안내하세요. 쿼터를 올려도 크레딧은 1도 늘지 않습니다.
:::
