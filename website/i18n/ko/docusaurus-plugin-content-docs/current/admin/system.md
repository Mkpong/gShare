# 시스템 설정

**운영 → 시스템**에는 인스턴스 전체 설정이 있습니다. 저장하는 즉시 적용되고, 모든 변경이 감사에
남습니다.

## 브랜딩

![브랜딩](/img/screens/admin-system.png)

사이드바, 로그인 화면, 브라우저 탭에 표시되는 **서비스 이름**과 **로고**입니다. 이름은 40자 이내,
로고는 PNG·JPEG·WebP·SVG로 180KB 이하이며 정사각형에 가까울수록 잘 맞습니다. 로고가 없으면 이름의
첫 글자가 아이콘이 됩니다.

스테이징 인스턴스를 프로덕션이 *아니라고* 눈에 띄게 만드는 가장 빠른 방법이 이름 변경입니다.

## 회원가입 {#회원가입}

![가입 정책](/img/screens/admin-system-signup.png)

| 방식 | 동작 |
|---|---|
| **받지 않음** | 로그인 화면에 가입 탭이 없습니다. 계정은 관리자만 만듭니다 |
| **승인 후 사용** | 누구나 가입할 수 있고, 관리자가 승인할 때까지 **대기** 상태입니다 |
| **바로 사용** | 가입 즉시 사용할 수 있습니다 |

**가입 가능한 이메일 도메인**은 쉼표로 구분한 목록이고, 비우면 어떤 주소든 허용합니다. 하위 도메인은
따로 적어야 합니다. 공유되거나 인터넷에서 닿는 인스턴스라면 *승인* 방식이더라도 설정하세요. 승인
대기열이 의미를 유지합니다.

새 계정은 **부서 없음** 상태로 시작하므로 크레딧도 노드 풀 권한도 없습니다.
[승인 대화 상자](./users-add.md#셀프-가입-승인)가 부서를 묻는 이유이고, 부서 없이 승인된 계정은
로그인은 되지만 아무것도 할 수 없습니다.

## GPU 배치

![배치 정책](/img/screens/admin-system-placement.png)

여러 카드가 조건을 만족할 때 공유 세션을 어느 카드에 올릴지 정합니다.

| 정책 | 동작 | 언제 |
|---|---|---|
| **모아 담기(binpack)** | 조건을 만족하는 카드 중 가장 많이 찬 카드에 올림 | 큰 세션을 위해 빈 카드를 남겨 두고 싶을 때 — 보통의 기본값 |
| **펼치기(spread)** | 가장 비어 있는 카드에 올림 | 세션마다 여유를 최대한 주고 싶을 때. 플릿이 조각나는 대가를 치릅니다 |

binpack은 전용·XL 티어를 더 오래 배치 가능하게 유지하고, spread는 한가한 클러스터에서 개별 처리량에
유리합니다. **새 배치에만** 영향을 주며 이미 있는 것은 움직이지 않습니다.

## 여기에 없는 설정

플랫폼이 배포되는 방식을 바꾸는 것 — 레플리카, 데이터베이스, 인그레스, 오퍼레이터 플래그, 보존
기간 — 은 콘솔이 아니라 Helm 값에 있습니다.
[레퍼런스 → Helm 값](../reference/helm-values.md)을 보세요.
