# 시스템 설정

**운영 → 시스템** 메뉴에서는 플랫폼 인스턴스 전체에 적용되는 제반 설정을 관리합니다. 설정 변경 사항은 저장 즉시 시스템에 적용되며, 모든 변경 이력은 감사 로그에 보관됩니다.

## 브랜딩

![브랜딩](/img/screens/admin-system.png)

사이드바, 로그인 화면, 브라우저 탭 아이콘에 표시될 **서비스 이름** 및 **로고 이미지**를 설정합니다. 서비스 이름은 최대 40자까지 입력 가능하며, 로고 파일은 PNG·JPEG·WebP·SVG 형식을 지원합니다 (파일 크기 180KB 이하, 정사각형 형태 권장). 별도의 로고를 등록하지 않은 경우 서비스 이름의 첫 글자가 기본 아이콘으로 적용됩니다.

스테이징 및 테스트 환경을 운영 프로덕션 환경과 명확히 식별하고자 할 때 서비스 이름을 다르게 지정하여 구분할 수 있습니다.

## 회원가입 {#회원가입}

![가입 정책](/img/screens/admin-system-signup.png)

| 방식 | 동작 |
|---|---|
| **받지 않음** | 로그인 화면에 회원가입 탭이 노출되지 않습니다. 계정 생성은 관리자를 통해서만 가능합니다. |
| **승인 후 사용** | 사용자가 자율적으로 가입을 신청할 수 있으나, 관리자의 승인이 완료될 때까지 **대기** 상태로 유지됩니다. |
| **바로 사용** | 가입 즉시 계정이 활성화되어 시스템을 사용할 수 있습니다. |

**가입 허용 이메일 도메인**은 쉼표(`,`)로 구분하여 등록하며, 빈 값으로 설정할 경우 모든 이메일 도메인의 가입을 허용합니다. 하위 도메인(Subdomain)은 별도로 명시해야 합니다. 외부망에 노출된 인스턴스인 경우, *승인 후 사용* 정책을 사용하더라도 무분별한 가입 신청을 방지하기 위해 가입 허용 도메인을 지정하는 것을 권장합니다.

신규 생성된 계정은 기본적으로 **부서 미지정** 상태로 시작되므로 자원 크레딧 및 노드 풀 접근 권한이 부여되지 않습니다. 따라서 [가입 승인 대화 상자](./users-add.md#셀프-가입-승인-관리)에서 소속 부서를 반드시 지정해야 하며, 부서 없이 승인된 계정은 로그인 후 서비스 이용이 제한됩니다.

## GPU 배치

![배치 정책](/img/screens/admin-system-placement.png)

복수의 GPU 카드가 세션 생성 조건을 만족할 때, 공유(Shared) 세션을 배치할 GPU 카드를 선정하는 알고리즘을 설정합니다.

| 정책 | 동작 방식 | 주요 사용 시점 |
|---|---|---|
| **모아 담기(Binpack)** | 요구 사항을 충족하는 GPU 카드 중 점유율이 가장 높은 카드에 세션을 우선 배치합니다. | 대형 자원이 필요한 세션을 위해 완전히 비어 있는 카드를 최대한 확보하고자 할 때 유용합니다 (기본값). |
| **펼치기(Spread)** | 요구 사항을 충족하는 GPU 카드 중 가장 여유로운(점유율이 낮은) 카드에 세션을 고르게 분산 배치합니다. | 각 세션의 자원 여유 폭을 최대한 확보하려는 경우 사용하며, 단일 카드의 분할 파편화(Fragmentation)가 발생할 수 있습니다. |

Binpack 알고리즘은 전용(Dedicated) 또는 고사양 XL 티어 세션의 배치 가능성을 오래 유지해 주며, Spread 알고리즘은 여유 있는 클러스터에서 각 세션의 단독 처리 성능을 높이는 데 유리합니다. 해당 배치 정책은 **신규 세션 배치 시에만 적용**되며, 이미 실행 중인 기존 세션의 위치는 변경되지 않습니다.

## 콘솔 외 인프라 설정 항목

플랫폼의 인프라 배포 방식(파드 레플리카 수, 데이터베이스 연동, 인그레스 설정, 오퍼레이터 플래그, 데이터 보존 기간 등)에 대한 변경은 콘솔 화면이 아닌 Helm 차트 설정값(Values)을 통해 관리됩니다. 자세한 내용은 [레퍼런스 → Helm 값](../reference/helm-values.md) 문서를 참조하세요.
