# 노드

모든 클러스터에서 오퍼레이터가 보고하는 모든 노드입니다.

![노드](/img/screens/admin-nodes.png)

| 열 | 의미 |
|---|---|
| **클러스터 / 역할** | 어느 클러스터인지, 그리고 GPU / CPU / master / storage |
| **노드** | 호스트명. 카드 목록으로 이어집니다 |
| **풀** | 속한 [노드 풀](./node-pools.md). 그 자리에서 바꿀 수 있습니다 |
| **모드** | 노드 라벨에 따른 분할 또는 전용 |
| **GPU / 실행 중 세션** | 카드와 그 위의 세션 |
| **CPU / 메모리 / 디스크** | 호스트 용량 |
| **상태** | 정상, 사용 중, 차단, 오프라인 |
| **하트비트** | 마지막 보고 경과 |

노드는 **콘솔에서 등록하지 않습니다**. 오퍼레이터의 인벤토리 컨트롤러가 보고하고 제어 플레인이
(클러스터, 호스트명)으로 upsert합니다. 새 기계는 클러스터에 조인한 뒤 1분 안에 저절로 나타납니다.

## 생존 판정

`api.nodeStaleSec`(5분) 동안 보고가 없는 노드는 자동으로 **오프라인**이 되고, 보고가 재개되면
**정상**으로 돌아옵니다. 오퍼레이터가 노드 자체의 Ready 상태를 보고하므로, kubelet이 멈춘 기계는
타임아웃을 기다리지 않고 즉시 오프라인이 됩니다.

노드가 오프라인이 되면 **실행 중 세션은 종료·정산**되고(`node_offline`), 일시정지 세션은 다른 곳에서
재개하도록 그대로 둡니다. 전환마다 모든 시스템 관리자에게 알림이 가므로, 조용히 빠진 기계도 화면을
지켜보지 않고 알 수 있습니다.

## 차단(cordon)

**차단**은 새 배치를 멈춥니다. 이미 실행 중인 세션은 그대로입니다. 차단은 약 15초 안에 Kubernetes
노드에도 반영되므로, kube-scheduler가 배치하는 CPU 세션조차 다시 올라오지 않습니다.

점검 전에, 그리고 비우기 전에 쓰세요.

## 비우기(drain) {#비우기}

![비우기](/img/screens/admin-node-drain.png)

**비우기**는 노드를 차단한 뒤 그 위의 것을 처리합니다. 두 가지 방식이 있습니다.

| 방식 | 세션마다 일어나는 일 |
|---|---|
| **재배치**(기본) | 콜드 일시정지 후 다른 곳에서 즉시 재개. GPU 세션은 같은 모델의 여유 있고 풀 권한이 있는 카드가, CPU 세션은 다른 CPU 노드가 필요합니다. 갈 곳이 없는 세션은 **대기 보관**됩니다. 일시정지 상태로 대기열의 자리를 지키고, 자리가 나면(다른 세션이 끝나거나 이 노드를 차단 해제하면) 큐 티커가 재개합니다 |
| **강제 종료** | 모든 세션을 관리자 종료처럼 정산 |

거의 항상 재배치가 정답입니다. 작업이 살아남고, 소유자에게는 종료가 아니라 일시정지와 재개로
보이며, 그 사이는 과금되지 않습니다.

페이지가 확정 전에 노드 위의 내용을 보여 줍니다. 세션, 소유자, 쥐고 있는 카드.

## 노드 삭제

**삭제**는 **오프라인** 노드에만 나타납니다. 오퍼레이터가 아직 보고하는 노드는 다음 인벤토리 틱에
다시 나타나기 때문입니다.

살아 있는 할당이나 비종료 세션이 남아 있으면 거부됩니다(`node_busy`). 노드와 GPU 카드 기록을
지우면서 **과금 이력은 유지**합니다. 과거 할당은 `gpu_uuid`를 가진 채, 더 이상 없는 카드와 분리되어
남습니다.

노드의 마지막 카드를 지우면 그 카드가 속했던 전용 풀이 비게 됩니다. 다른 노드를 배정하거나 풀을
삭제하세요.

기계 수준 절차 — `kubectl drain`, `kubeadm reset`, 새 노드 라벨 — 는
[클러스터 구축](../cluster-setup.md#growing-or-shrinking-a-running-cluster)에 있습니다.
