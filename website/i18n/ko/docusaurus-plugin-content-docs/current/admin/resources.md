# 자원, 오퍼링, 프리셋, 정책

**자원 → 자원 설정**(시스템 관리자)은 세션 마법사의 바탕이 되는 카탈로그이고, **자원 → 자원 정책**은
각 사용자가 요청할 수 있는 양을 정하는 한도 모음입니다.

## 오퍼링

![오퍼링 카탈로그](/img/screens/admin-resources.png)

**오퍼링**은 GPU 모델 하나를 과금 가능한 상품으로 만든 것입니다. 모델 문자열, 카드 전체의 VRAM과
코어, 크레딧 **시간당 단가**, 이미지가 지원해야 하는 최소 CUDA 버전. *클러스터 보유* 태그는 모델
문자열이 플릿이 지금 보고하는 카드와 일치하는 오퍼링을 표시합니다.

:::caution 모델 문자열은 정확히 일치해야 합니다
스케줄러는 드라이버가 보고하는 모델(예: `NVIDIA GeForce RTX 4090`)과 문자열이 같은 오퍼링을
찾습니다. 오퍼링을 만들 때 [GPU 디바이스](./gpus.md) 페이지에서 복사하세요. 플릿이 더 긴 SKU를
보고하고 그 접두어(단어 경계)인 오퍼링이 정확히 하나뿐이면, 그 오퍼링이 보고된 문자열을 자동으로
받아들입니다(`offering.align_model`로 감사 기록).
:::

## 프리셋

**프리셋**은 컴퓨트 형태(CPU, 메모리, 임시 디스크)와 GPU 분할 티어 — XL ½, L ¼, M ⅛, S 1/16,
SS 1/32 — 또는 전용 카드를 짝지은 것입니다. 사용자가 마법사에서 처음 고르는 것이 프리셋이며, 가격은
오퍼링 단가 × 비율로 정해집니다.

## 자원 정책

![자원 정책](/img/screens/admin-policies.png)

**정책**은 대상이 한 번에 쥘 수 있는 양을 제한합니다. 동시·대기 세션 수, VRAM, GPU 코어, 호스트
CPU·메모리·디스크, 볼륨 쿼터, 최대 세션 실행 시간, 그리고 GPU 세션이 일시정지되는 유휴 시간. 정책은
**가장 구체적인 것부터** 적용됩니다. **사용자 → 부서 → 조직 → 전역**. 정책으로 전용 노드 풀 접근을
줄 수도 있습니다.

![새 정책](/img/screens/admin-policy-new.png)

크레딧은 GPU 세션에만 적용됩니다. CPU 세션과 볼륨은 무료이므로 정책의 동시 실행 수와 자원 상한으로
제한하세요. 사용자의 **쿼터 요청**(대시보드의 *증액 요청*)은 이 페이지에서 승인을 기다립니다.

## 세션 이미지

카탈로그는 CUDA 12.4/12.5 계열과 Blackwell(CUDA 12.8/12.9) 계열의 `boanlab/gshare-session:<tag>`
이미지를 시드합니다. Blackwell 카드 플릿은 12.8 계열이 필요하며, 이전 이미지는
`incompatible_image`로 거부됩니다. [이미지](./images.md)를 참고하세요.
