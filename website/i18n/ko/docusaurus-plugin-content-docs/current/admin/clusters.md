# 클러스터

**클러스터**는 gShare 오퍼레이터가 도는 Kubernetes 클러스터 하나입니다. 제어 플레인은 사용자·돈·
결정을 쥐고, 각 클러스터는 그 결정을 파드로 바꾸고 실제로 일어난 일을 보고합니다.

| 페이지 | 내용 |
|---|---|
| [노드](./nodes.md) | 기계: 차단, 비우기, 삭제, 생존 판정 |
| [노드 풀](./node-pools.md) | 특정 테넌트를 위한 노드 예약 |

![클러스터](/img/screens/admin-clusters.png)

| 열 | 의미 |
|---|---|
| **클러스터** | 이름과 ID(`clu_…`) — 오퍼레이터에 지정한 그 ID |
| **API 주소** | 제어 플레인이 세션 리소스를 적용하는 주소 |
| **세션 도메인** | 이 클러스터의 세션이 서비스되는 호스트명. 미지정이면 제어 플레인 도메인 |
| **상태** | connected, 또는 연결 프로브의 마지막 오류 |
| **노드 / GPU / 실행 세션** | 플릿에 기여하는 양 |
| **하트비트** | 마지막 인벤토리 보고 경과 |

행을 누르면 그 클러스터의 노드가 펼쳐집니다.

![클러스터의 노드](/img/screens/admin-cluster-nodes.png)

## 등록

![클러스터 등록](/img/screens/admin-cluster-register.png)

제어 플레인 자신의 클러스터는 설치 시 자동 등록됩니다(`bootstrapLocalCluster`). 추가 클러스터는
보통 `hack/attach-cluster.sh`로 등록하는데, 이 스크립트가 등록과 함께 오퍼레이터·HAMi·인그레스와
(선택적으로) CSI 드라이버까지 한 번에 설치합니다. [멀티 클러스터](../multi-cluster.md)를 보세요.

이 대화 상자로 직접 등록할 때는 이름과 kubeconfig가 필요합니다. 제출하면 제어 플레인이 받아들이기
전에 **프로브**합니다. API 서버 도달, RuntimeClass `nvidia`, HAMi의 `nvidia.com/gpumem` 광고. 실패하면
어느 검사가 실패했는지 알려 줍니다.

꼭 맞춰야 할 두 가지:

- **kubeconfig의 `server:`는 제어 플레인 파드에서 닿아야** 합니다. 내 노트북에서가 아닙니다.
  kubeadm `admin.conf`의 `127.0.0.1`이 전형적인 실패입니다.
- **클러스터 ID는 여기서 발급됩니다.** 그 클러스터의 오퍼레이터는 정확히 이 `clusterId`로 배포되어야
  하고, 아니면 인벤토리와 상태 콜백이 거부됩니다.

kubeconfig는 데이터베이스에 평문으로 저장되지 않고 시크릿 참조만 보관됩니다.

## 세션 도메인

클러스터마다 자기 세션 URL을 서비스합니다. 파드로 라우팅하는 것이 그 클러스터의 인그레스이기
때문입니다. **세션 도메인**은 그 클러스터 인그레스로 해석되는 호스트명이어야 합니다.
`attach-cluster.sh --session-domain`으로 설정하거나, 나중에 `PATCH /api/v1/clusters/{id}`
(`session_domain`)로 바꿉니다. 콘솔은 표시만 하고 편집하지 않습니다. 비워 두면 사용자가 제어 플레인
도메인으로 안내되어 모든 연결이 404가 됩니다. 멀티 클러스터에서 가장 흔한 실수가 이 필드 하나입니다.

## 등록 해제

살아 있는 세션이나 할당이 있으면 거부됩니다. 제거되면:

- 노드·GPU 디바이스·스토리지 풀이 콘솔에서 정리되고,
- 세션 **이력은 남습니다**. 원장이 참조하기 때문입니다.
- 그 클러스터의 오퍼레이터는 지울 때까지 계속 돌지만 콜백은 거부됩니다.

클러스터의 자격 증명을 바꾸려면 등록 해제 후 재등록해야 하고, 그러면 새 ID가 발급됩니다. 오퍼레이터
Helm 값을 함께 준비해 두고 진행하세요.
