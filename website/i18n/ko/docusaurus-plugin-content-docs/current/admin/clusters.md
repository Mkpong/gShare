# 클러스터와 노드

## 클러스터

![클러스터](/img/screens/admin-clusters.png)

**클러스터**는 gShare 오퍼레이터가 도는 Kubernetes 클러스터 하나입니다. 제어 플레인 자신의
클러스터는 설치 시 자동 등록되고, 추가 클러스터는 `hack/attach-cluster.sh`로 연결합니다
([멀티 클러스터](../multi-cluster.md) 참고). 목록은 각 클러스터의 연결 상태, 세션이 서비스되는
도메인, 노드·GPU 수를 보여 줍니다. 등록 해제는 노드·디바이스·스토리지 풀을 정리하며, 실행 중인
세션은 먼저 정산됩니다.

## 노드

![노드](/img/screens/admin-nodes.png)

오퍼레이터가 보고하는 모든 노드를 클러스터, 역할(GPU, CPU, master, storage), 노드 풀, GPU 수, 실행
중 세션, 호스트 자원, 하트비트 경과와 함께 나열합니다.

노드 상태는 오퍼레이터의 인벤토리 하트비트가 정합니다. 5분간 보고가 없는 노드는 자동으로
**오프라인**이 되고 보고가 재개되면 **정상**으로 돌아옵니다. 오퍼레이터는 노드 자체의 Ready 상태를
보고하므로 kubelet이 멈춘 기계는 즉시 오프라인이 됩니다. 전환마다 모든 시스템 관리자에게 알림이
갑니다.

### 노드별 작업

- **차단 / 차단 해제** — 새 배치를 멈추거나 재개합니다. 실행 중 세션은 그대로입니다.
- **비우기** — 차단한 뒤 노드 위의 세션을 옮기거나 끝냅니다. *재배치*는 실행 중 세션마다 콜드
  일시정지 후 여유 있는 다른 노드에서 즉시 재개합니다. 갈 곳이 없는 세션은 대기열에 두었다가 자리가
  나면 재개합니다. *강제 종료*는 모든 세션을 정산합니다. 차단은 Kubernetes 노드에도 반영되어
  아무것도 다시 배치되지 않습니다.
- **삭제** — **오프라인** 노드에서만 제공됩니다(오퍼레이터가 아직 보고하는 노드는 다음 틱에 다시
  나타납니다). 살아 있는 할당이 남아 있으면 거부되고, 과금 이력은 유지됩니다.

### 노드 풀

**노드 풀** 탭은 노드를 풀로 묶어 [자원 정책](./resources.md)이 특정 테넌트에 줄 수 있게 합니다.
전용 풀의 카드는 다른 모두의 배치에서 보이지 않습니다.

기계 수준 절차 — join, 라벨, drain, `kubeadm reset` — 는
[클러스터 구축](../cluster-setup.md#growing-or-shrinking-a-running-cluster)에 있습니다.
