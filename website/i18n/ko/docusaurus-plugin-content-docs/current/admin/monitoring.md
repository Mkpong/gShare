# 세션 관제

**운영 → 세션 관제**는 내 범위에서 도는 모든 것을 서버 전송 이벤트 스트림으로 실시간 갱신하는
화면입니다. *LIVE* 배지가 스트림 연결 상태를 알려 줍니다(끊기면 조용히 폴링으로 대체합니다).

| 페이지 | 내용 |
|---|---|
| [개입하기](./monitoring-control.md) | 강제 종료, 일괄 정리, 대기열 |

![세션 관제](/img/screens/admin-monitor.png)

## 표

| 열 | 의미 |
|---|---|
| **세션** | 이름과 ID. 행을 누르면 타임라인이 열립니다 |
| **상태** | 실행중, 대기, 일시정지, 종료됨 |
| **사용자 / 조직 / 부서** | 누구의 것인지. 관리자가 정렬하는 범위 열입니다 |
| **자원** | 클래스, 모드, VRAM, 코어 비율 |
| **노드 / 클러스터** | 실제로 도는 위치 |
| **마지막 동작** | 마지막 전환 시각 |

검색은 세션 이름·ID·소유자를 찾습니다. 필터는 상태·조직·부서로, 상단 바의 클러스터 선택은
클러스터로 좁힙니다.

## 범위

범위는 세션에 붙은 라벨이 아니라 **소유자**를 따릅니다.

- **부서 관리자**는 자기 부서 구성원의 세션을 봅니다.
- **조직 관리자**는 조직의 모든 세션을 봅니다.
- **시스템 관리자**는 플릿 전체를 봅니다.

![부서 관리자 화면](/img/screens/admin-monitor-group.png)

부서를 지정하지 않고 만든 세션도 소유자의 소속에 속하므로, 알맞은 관리자에게만 보입니다.

## 세션 타임라인

![세션 하나](/img/screens/admin-monitor-detail.png)

행을 열면 그 세션의 전체 이벤트 타임라인이 보입니다. 대기(얼마나 기다렸는지), 시작, 일시정지,
재개, 종료 — 각각 당시 기록된 사유와 함께. 사용자가 "내 세션 왜 멈췄어요"라고 물을 때 가장 먼저 볼
곳입니다.

## 세션 생존 판정 — 스스로 끝나는 경우

오퍼레이터는 실행 중인 모든 세션을 1분마다 다시 보고하고, 제어 플레인은 들은 것에만 근거해
움직입니다.

| 규칙 | 조건 | 결과 |
|---|---|---|
| **크래시 루프** | 컨테이너가 3회 재시작 후 `CrashLoopBackOff` | 종료(`crash_loop`), 정산, 소유자 알림 |
| **파드 유실** | *오퍼레이터는 살아 있는데* 5분간 하트비트 없음 | 정산(`pod_lost`) |
| **오퍼레이터 침묵** | 한 클러스터의 모든 노드가 동시에 stale | **아무것도 건드리지 않음** — 오퍼레이터 장애가 대량 종료가 되어서는 안 됩니다 |
| **노드 오프라인** | kubelet이 응답을 멈춤 | 그 위의 실행 세션 종료(`node_offline`), 일시정지 세션은 다른 곳에서 재개 |
| **유휴** | 정책의 유휴 시간 초과 | 세션 **일시정지**, 카드 반환 |
| **최대 실행 시간** | 정책 상한 초과 | 세션 종료 |
| **파드 수동 삭제** | 세션은 아직 필요한데 파드만 삭제됨 | 파드를 다시 생성. 과금과 예약은 그대로 |

이 모든 것이 세션 타임라인과 소유자 알림에 남습니다. 조용히 끝나는 것은 없습니다.
