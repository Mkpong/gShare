# 세션 관제

**운영 → 세션 관제** 메뉴는 관리 권한(범위) 내에서 실행되는 모든 세션의 정보를 서버 전송 이벤트(SSE) 스트림을 통해 실시간으로 갱신하여 보여주는 화면입니다. *LIVE* 배지를 통해 스트림 연결 상태를 확인할 수 있으며, 연결이 끊어질 경우 자동으로 폴링(Polling) 방식으로 전환하여 모니터링을 유지합니다.

| 페이지 | 내용 |
|---|---|
| [개입하기](./monitoring-control.md) | 강제 종료, 일괄 정리, 대기열 관리 |

![세션 관제](/img/screens/admin-monitor.png)

## 표

| 열 | 의미 |
|---|---|
| **세션** | 세션 이름 및 ID (해당 행을 클릭하면 상세 타임라인이 열립니다.) |
| **상태** | 실행 중, 대기, 일시정지, 종료됨 |
| **사용자 / 조직 / 부서** | 세션 소유자 정보 (관리자가 정렬 및 조회 범위를 설정하는 기준 열입니다.) |
| **자원** | 자원 클래스, 실행 모드, VRAM, CPU 코어 비율 |
| **노드 / 클러스터** | 세션이 실제로 실행되는 물리/논리적 위치 |
| **마지막 동작** | 마지막으로 상태가 변경(전환)된 시각 |

검색 기능을 통해 세션 이름, ID, 소유자를 조회할 수 있으며, 상단 필터에서 상태·조직·부서를 선택하거나 클러스터 선택 메뉴를 통해 특정 클러스터 단위로 조회 범위를 좁힐 수 있습니다.

## 범위

조회 및 관리 범위는 세션에 부여된 라벨이 아닌 **소유자의 권한 범위**를 기준으로 결정됩니다.

- **부서 관리자**: 자신이 속한 부서 구성원들의 세션을 조회하고 관리합니다.
- **조직 관리자**: 조직 내 전체 구성원의 세션을 조회하고 관리합니다.
- **시스템 관리자**: 클러스터 플릿 전체의 모든 세션을 조회하고 관리합니다.

![부서 관리자 화면](/img/screens/admin-monitor-group.png)

별도의 부서를 지정하지 않고 생성한 세션도 소유자의 소속 부서에 귀속되므로, 해당 권한을 가진 관리자에게만 노출됩니다.

## 세션 타임라인

![세션 하나](/img/screens/admin-monitor-detail.png)

목록에서 해당 행을 클릭하면 해당 세션의 전체 이벤트 타임라인이 표시됩니다. 대기 시간(대기열 체류 시간), 시작, 일시정지, 재개, 종료 등 각 상태 전환 시점에 기록된 사유를 함께 확인할 수 있습니다. 사용자가 세션 중지 원인을 문의할 때 가장 먼저 참조해야 하는 화면입니다.

## 세션 생존 판정 — 자동 종료 및 상태 전환

오퍼레이터는 실행 중인 모든 세션의 상태를 1분마다 주기적으로 보고하며, 제어 플레인(Control Plane)은 오퍼레이터가 전달한 보고 상태를 기반으로 동작을 수행합니다.

| 규칙 | 조건 | 결과 |
|---|---|---|
| **크래시 루프** | 컨테이너가 3회 재시작 후에도 실패하여 `CrashLoopBackOff` 상태로 전환된 경우 | 세션 종료(`crash_loop`), 자원 정산 및 소유자 알림 발송 |
| **파드 유실** | *오퍼레이터는 정상 작동 중이나* 특정 파드에서 5분간 하트비트가 없는 경우 | 세션 정산(`pod_lost`) |
| **오퍼레이터 응답 없음** | 특정 클러스터 내 모든 노드가 동시에 응답 불가(Stale) 상태가 된 경우 | **기존 세션을 유지하고 아무 작업도 수행하지 않음** (오퍼레이터 장애가 대규모 세션 강제 종료로 이어지는 것을 방지) |
| **노드 오프라인** | kubelet이 응답을 중단한 경우 | 해당 노드에서 실행 중이던 세션 종료(`node_offline`), 일시정지된 세션은 다른 노드에서 재개 |
| **유휴 상태 초과** | 설정된 유휴 제한 시간을 초과한 경우 | 세션 **일시정지** 및 GPU 자원 반환 |
| **최대 실행 시간 초과** | 설정된 최대 실행 상한 시간을 초과한 경우 | 세션 자동 종료 |
| **파드 수동 삭제** | 세션 유지는 필요하나 파드만 수동으로 삭제된 경우 | 파드 자동 재생성 (과금 및 자원 예약 상태 유지) |

상기 모든 이벤트 및 생존 판정 결과는 세션 타임라인과 소유자 알림에 기록됩니다. 명확한 이력 남김 없이 임의로 종료되는 세션은 없습니다.
