# 세션 관제

**운영 → 세션 관제**는 내 범위의 모든 세션과 대기열 항목을 서버 전송 이벤트 스트림(*LIVE* 표시)으로
실시간 갱신하는 화면입니다.

![세션 관제](/img/screens/admin-monitor.png)

각 행은 세션, 상태, 사용자, 조직, 부서, 자원(클래스, 모드, VRAM, 코어 비율), 마지막 동작을 보여
줍니다. 열마다 정렬하고, 세션 이름·ID·소유자로 검색하고, 상태·조직·부서로 필터합니다. 조직
관리자는 자기 조직의 세션만, 부서 관리자는 자기 부서의 세션만 봅니다. 범위는 세션의 **소유자**를
따르므로 부서 없이 만든 세션도 소유자의 소속에 속합니다.

## 강제 종료

행의 **강제 종료**는 소유자 동의 없이 세션을 끝냅니다. 소유자가 직접 멈춘 것처럼 정산되고, GPU가
반환되며, 소유자에게 알림이 갑니다. 입력한 사유는 감사 로그에 남습니다.

여러 행을 체크하면 고정 툴바의 버튼이 활성화됩니다 — **강제 종료 (N)**, **일괄 정리 (N)**. 일괄
종료는 세션이 다른 사람의 것이므로 건수를 입력하도록 요구합니다.

## 대기열 탭

**대기열** 탭은 용량을 기다리는 세션을 순번, 우선순위, 대기 사유와 함께 나열합니다. 관리자는 항목을
취소하거나 우선순위를 올릴 수 있습니다.

## 세션 생존 판정

오퍼레이터는 실행 중인 모든 세션을 1분마다 다시 보고하고, 제어 플레인은 들은 것에만 근거해
움직입니다. 추정으로 움직이지 않습니다.

- **크래시 루프** — 컨테이너가 세 번 재시작되고 `CrashLoopBackOff`에 머물면 세션을 끝냅니다
  (`crash_loop`, 정산·알림). 끝없는 재시작에 과금하지 않습니다.
- **파드 유실** — 오퍼레이터는 살아 있는데 세션 하트비트가 5분간 없으면 정산합니다(`pod_lost`).
  오퍼레이터 자체가 침묵하면 아무것도 건드리지 않습니다. 오퍼레이터 장애가 대량 종료로 이어져서는
  안 됩니다.
- **노드 오프라인** — kubelet이 응답을 멈춘 노드는 즉시 오프라인이 되고 그 위의 실행 세션은
  끝납니다(`node_offline`). 일시정지된 세션은 다른 곳에서 재개하도록 남겨 둡니다.
- 세션이 아직 필요한데 파드가 수동 삭제(또는 축출)되면 그냥 다시 만듭니다.

## 모니터링 페이지

![모니터링](/img/screens/admin-monitoring.png)

**운영 → 모니터링**(시스템 관리자)은 [모니터링 스택](../operations/observability.md)이 배포되어
있을 때 Prometheus에서 노드별·카드별 GPU 사용률, VRAM, 호스트 지표를 차트로 보여 줍니다.
