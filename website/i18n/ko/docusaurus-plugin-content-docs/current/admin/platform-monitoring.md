# 지표와 사용률

**운영 → 모니터링**은 하드웨어가 실제로 무엇을 하고 있는지를 DCGM과 node-exporter, Prometheus를
거쳐 그립니다. 콘솔의 다른 모든 곳에 있는 할당 수치의 짝입니다.

![GPU 지표](/img/screens/admin-monitoring.png)

| 탭 | 내용 |
|---|---|
| **GPU** | 카드별 사용률, 사용 중 VRAM, 온도와 전력. 노드별·카드별 |
| **호스트** | 노드별 CPU, 메모리, 디스크, 네트워크 |

기간 선택과 자동 새로고침은 상단에, 노드 필터로 한 기계만 볼 수 있습니다.

![호스트 지표](/img/screens/admin-monitoring-host.png)

## 할당 대 사용

차트 아래 표가 중요한 대조입니다.

> 그래프는 카드가 실제로 하고 있는 일이고, 표는 제어 플레인이 할당한 기록입니다.

분할된 카드는 여러 세션이 나눠 쓰므로 그래프만으로 한 세션을 특정할 수 없습니다. 두 화면이 함께
있는 이유입니다. 봐야 할 패턴:

| 할당 | 사용률 | 의미 |
|---|---|---|
| 높음 | 높음 | 진짜로 꽉 찼습니다. 하드웨어를 늘리거나 쿼터를 조이세요 |
| 높음 | 낮음 | 놀고 있는 예약입니다. **유휴 시간**을 줄이고 더 작은 [티어](./resources-presets.md)를 제공하세요 |
| 낮음 | 높음 | 소수가 전용 카드에서 무겁게 돌립니다. 가격이나 풀 정책을 검토하세요 |

## 화면이 비어 있을 때

지표에는 모니터링 스택이 필요합니다. `make deploy-monitoring`이 dcgm·node·kube-state 익스포터와 함께
Prometheus를 설치합니다. 없으면 콘솔이 메트릭 백엔드에 연결할 수 없다고 말하고, 더 중요하게는
`operator.hamiMonitorUrl`이나 `operator.prometheusUrl`이 설정되지 않는 한 **유휴 리퍼에 사용률
소스가 없습니다**.

각 익스포터가 무엇을 제공하는지를 포함한 상세는
[운영 → 관측](../operations/observability.md)에 있습니다.

Prometheus는 클러스터 밖에 노출되지 않습니다. 콘솔은 `gshare-api`를 통해 읽고, API가 쿼리를
화이트리스트로 제한하며 시스템 관리자 권한을 강제합니다.
