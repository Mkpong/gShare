# 사용자

**조직 → 사용자 관리**는 내 범위의 모든 계정을 역할·소속과 함께 보여 줍니다.

| 페이지 | 내용 |
|---|---|
| [사용자 추가](./users-add.md) | 한 명씩, CSV 일괄, 셀프 가입 승인 |
| [계정 관리](./users-manage.md) | 편집, 역할, 비밀번호 초기화, 비활성화, 삭제 |

![사용자](/img/screens/admin-users.png)

## 목록이 보여 주는 것

| 열 | 의미 |
|---|---|
| **사용자** | 이름과 이메일(복사 버튼 포함). 이메일이 로그인 아이디입니다 |
| **조직 / 부서** | 소속. 여러 부서에 속할 수 있습니다 |
| **역할** | 가진 역할 전부. 각각 범위가 붙습니다 — *조직 관리자 · Nexus AI Lab*, *멤버 · 비전팀* |
| **상태** | *활성*, *대기*(승인 대기), *비활성* |
| **생성** | 계정이 만들어진 시각 |
| **작업** | 승인(대기 계정), 편집, 비활성화/활성화, 삭제 |

역할은 **다른 곳에서 부여**하고 여기서는 보기만 합니다. 전역 역할은 [시스템](./system.md), 조직
관리자는 [조직](./organizations.md#조직-관리자), 부서 역할은 [부서](./groups.md#부서-관리자)에서.

![필터](/img/screens/admin-users-toolbar.png)

검색은 이름과 이메일을 찾고, 필터는 조직·부서·상태로 좁힙니다. 콘솔의 모든 목록이 그렇듯 필터는
주소창에 담기므로 그대로 공유할 수 있습니다.

## 범위

- **부서 관리자**는 자신이 관리하는 부서의 구성원을 봅니다.
- **조직 관리자**는 조직의 모든 사용자를 봅니다.
- **시스템 관리자**는 부서가 아직 없는 계정까지 포함해 전원을 봅니다. 막 승인된 가입자가 여기에
  들어옵니다.

범위 밖의 사용자는 보이지도, 수정되지도 않습니다. API도 콘솔과 무관하게 독립적으로 거부합니다.

## 소속이 정하는 것

소속은 라벨이 아닙니다. 소속이 정하는 것은:

- **어느 크레딧 풀**이 그 사람을 지원하는지 — 배분은 조직 → 부서 → 개인으로 흐릅니다
  ([크레딧](./credits.md));
- **어느 자원 정책**이 적용되는지 — 사용자 → 부서 → 조직 → 전역
  ([정책](./resources-policies.md));
- **어느 노드 풀**에 배치될 수 있는지 ([노드 풀](./node-pools.md));
- **누가 그 사람의 세션을 볼 수 있는지** ([관제](./monitoring.md), [감사 로그](./audit.md)).

부서가 없는 사용자는 크레딧도 풀 권한도 없습니다. 승인 대화 상자가 부서를 묻는 이유입니다.
