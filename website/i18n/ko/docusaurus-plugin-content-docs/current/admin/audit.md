# 감사 로그

권한·과금·세션·자원의 모든 변경이 불변 로그에 남습니다. 누가, 무엇을, 어느 대상에, 결과, 그리고
전후 상세.

![감사 로그](/img/screens/admin-audit.png)

조직 관리자는 자기 조직의 항목을, 부서 관리자는 자기 부서의 항목을, 시스템 관리자는 전부를 봅니다.
범위는 화면이 아니라 쿼리에 적용됩니다. 다른 테넌트의 행위가 새는 화면은 없습니다.

## 필터

| 필터 | 용도 |
|---|---|
| **행위자** | 이름 또는 이메일 — 한 사람이 한 모든 것 |
| **액션** | `session.force_terminate`, `credit.allocate`, `membership.update`, `user.set_global_role` … |
| **결과** | 성공 또는 거부. 거부(`access.denied`)도 기록됩니다 |
| **대상 ID** | 한 세션·지갑·사용자에게 *일어난* 모든 것 |
| **기간** | 1시간, 24시간, 1주일, 30일, 또는 직접 설정 |

필터는 주소창에 담기므로, 티켓에 붙여 넣은 쿼리가 상대에게도 정확히 같은 행을 재현합니다.

## 항목 읽기

![펼친 항목](/img/screens/admin-audit-detail.png)

행을 열면 전체 상세가 나옵니다. 인용할 식별자와, 레코드를 바꾼 작업이라면 **이전 → 이후** 비교.
역할 변경은 두 역할을, 정책 수정은 바뀐 모든 필드를 보여 줍니다.

## 내보내기

**CSV 내보내기**는 현재 보기 — 같은 범위와 필터로 모든 페이지 — 를 Excel이 바로 여는 UTF-8(BOM)
파일로 내려받습니다. 시각, 행위자, 액션, 결과, 대상, 조직, 부서, JSON 상세.

내보내기 자체도 기록됩니다(`audit.export`, 필터와 행 수 포함). 시스템 밖으로 나가는 파일도 다른
행위만큼 추적됩니다.

## 무엇이 기록되나

로그인과 실패 · 비밀번호 변경과 초기화 · 역할과 소속 변경 · 모든 크레딧 이동(배분, 회수, 승인,
반려, 충전) · 세션 생성·일시정지·재개·종료·강제 종료(사유 포함) · 볼륨 생성·공유·쿼터 변경·삭제·
강제 삭제 · 오퍼링·프리셋·정책 수정 · 노드 차단·비우기·삭제 · 클러스터 등록과 제거 · GPU 장애
표시와 복구 · 브랜딩·가입·배치 정책 변경 · 접근 거부(분당 중복 제거).

보존 기간은 차트에서 정합니다(`api.auditRetentionDays`, 기본 180일). `0`이면 전부 보관합니다.

## 실제로 통하는 조사 방법

| 질문 | 쿼리 |
|---|---|
| 이 세션은 왜 끝났나? | 대상 ID = 세션 ID |
| 이번 주에 누가 남의 세션을 끝냈나? | 액션 = `session.force_terminate`, 기간 = 1주일 |
| 이 조직의 크레딧은 어디로 갔나? | 행위자 = 조직 관리자, 액션 = `credit.*` |
| 누가 권한 없는 곳을 찔러 보나? | 결과 = 거부 |
| GPU 카탈로그를 누가 바꿨나? | 액션 = `offering.*` |
